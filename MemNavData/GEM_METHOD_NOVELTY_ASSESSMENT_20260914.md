# GEM 方法定位与下一步机制判断

2026-09-14，作者侧评估。依据当前主稿、实现、已完成实验和下列公开原始论文。本记录没有改动论文或实现，没有启动新的 GPU 实验，也没有重新查询 HPC 队列。

**判断：当前模块可以进入 Method；最新两项存储优化尚不足以单独支撑“新的神经记忆架构”。论文整体仍可围绕流式几何如何成为可用于跨目标导航的记忆展开。**

当前方法的完整链条是：冻结的流式几何状态与按帧索引的历史证据共同构成记忆；当前帧产生稠密深度；目标图像只读地检索历史见证帧；原有 SuperPoint、LightGlue 和 PnP 建立目标与见证帧的关系；共享几何将它变换到当前位置，形成可验证的导航线索。下游匹配和控制器保持原有接口。

当前新增的支持档案和读取精度 KV，使这条链的存储与执行方式更明确、更经济。它们的主要证据是输出保持和资源节约，尚未证明更好的跨时刻几何、记忆检索或导航成功率。

KV 成本的短历史写入均值为 164.191 → 165.250 ms/帧，长历史为 302.015 → 236.143 ms/帧。每项三个进程，同机有其他 GPU 进程；这些均值不能宣称隔离硬件条件下的确定加速，也不能换算成已经验证的闭环控制频率。

**现有支持档案可以写成有明确条件的方法设计。**

令历史帧的冻结检测点为 \(\mathcal P_h=\operatorname{SP}(I_h)\)，原读取器的双线性采样邻域为 \(\mathcal N(u)\)，保存位置为

\[
\Omega_h=\bigcup_{u\in\mathcal P_h}\mathcal N(u).
\]

除原 RGB、检索描述子和历史位姿外，只需保留 \(\Omega_h\) 上的原精度深度、置信度及原过滤器依赖的全局最小置信度。未来目标与历史图像的匹配使用这些已固定的历史检测点的子集，因此不需要在写入时知道未来目标。

在检测器及预处理固定、采样规则相同、所有被访问值和全局统计量均保留的条件下，历史档案压缩算子 \(C\) 可满足原读取器的条件等价性：

\[
\mathcal R_G(S_t,C(\mathcal E))
=\mathcal R_G(S_t,\mathcal E).
\]

这里保持的是指定读取器的输出，\(S_t\) 不变。该等式不适用于改变窗口、删减神经 tokens、替换检测器或要求任意历史稠密读出的情形；已有有限测试也不等于证明所有未来数值执行都逐比特一致。它适合作为存储设计的限定性质，不宜包装成普适场景压缩定理。

**最相关文献已经覆盖的内容。**

- [LingBot-Map / Geometric Context Transformer，2026-09-08 更新版](https://arxiv.org/html/2604.14141)：原生设计包括锚定上下文、近期稠密视图窗口与历史轨迹 tokens。局部窗口加长期特殊 tokens，以及通过 attention 访问它们，本身属于底座已有机制。
- [STAC，2026-03](https://arxiv.org/html/2603.20284)：结合累计注意力的时间缓存管理与按空间组织、合并和读取的长期缓存。一般性的 attention 重要性淘汰已经有直接相关工作。
- [GHOST，2026-05](https://arxiv.org/html/2605.15852)：从几何预测构造帧 / token 重要性并分配缓存预算。它也提示 attention 分数未必代表几何贡献；其具体相关性结果属于该论文设置，不能直接当作我们模型的测量。
- [XStreamVGGT，2026-01](https://arxiv.org/html/2601.01204)：研究基于 query-key 重要性的 KV 裁剪与量化。给现有 KV 再加一个通用 attention 选择器并不能自动建立独特贡献。
- [TTT3R](https://arxiv.org/html/2509.26645) 与 [ZipMap](https://arxiv.org/html/2603.04385)：研究用测试时更新的状态 / 快速权重表示几何信息。其更新算子与网络结构是方法的一部分，不能通过给现有缓存换名获得对应能力。

这些是机制关系的比较，没有将其他论文报告的显存、速度或精度与本地结果作跨设置排名。

**三项影响论文定位的关键问题。**

1. **新增机制与原主张的边界。** 主稿已有历史见证帧、共享几何与冻结策略之间的完整接口。最新改动进一步规定几何证据如何保存、缓存按何种精度存储。建议将其写成该接口的实现与效率设计，保持原 abstract / introduction 主线。若宣称新的神经记忆架构，仍缺少新的状态更新或保留机制及其独立效果。

2. **实验版本必须对应。** 主稿 Method 仍描述按需因果重放历史深度；当前候选已提前保存支持几何。旧主表不能直接改标成新候选。应在已提交 HPC 队列的完整归约后，明确哪些实验属于原方法、哪些验证新存储实现；复用已有成本和一致性证据，不重复跑未变化的版本。

3. **不能假定 attention 要解决检索问题。** 当前主稿的 21 个历史支持样本中，DINO top-8 覆盖 21/21；共视实验低支持区间中 GEM 为 32/40，直接检索基线为 39/40。前者说明该小组检索覆盖已足够，后者说明验证 / 几何读出的使用率和收益需要诚实解释。两者都不能单独确定失败根因，但已不支持“先增加一个 attention 检索器就会有效”的预设。

**关于进一步使用 LingBot tokens 的具体判断。**

更有意义的问题是：固定存储预算下，哪些历史 tokens 支撑了未来时刻与历史见证帧之间的相对几何？这一目标直接对应原 SP + LG + PnP 的输入质量，可以保持下游不变，也不要求改写论文的导航任务。

当前原生 attention 已使用历史 tokens；我们尚未建立其分数与这项任务价值的关系。注意力权重表示模型如何分配读取权重，删除后的几何影响则是另一个问题。通用累计 attention、几何启发式打分和学习一个淘汰阈值都不足以自动回答它。

如确实推进下一项机制，先做一次限定范围的因果诊断：从已有成功和失败轨迹固定选取少量时刻，比较移除相同大小历史 token 块前后，历史到当前的相对姿态以及固定读取器的方向是否改变；再检查相机 / 上下文 token 对这些历史块的 attention 是否能预测这种改变。采用相同预算的近期保留作为直接参照，不做窗口与阈值搜索。

这个诊断尚未实现、没有新结果。只有信号足够稳定、且获取成本可接受时，才值得据此设计写入保留机制；否则保留原生 W64，并把论文贡献放在已验证的任务接口和按读出需求保存的几何证据上。完整 attention 矩阵提取还可能抵消成本收益；本地 SDPA 路径目前不返回这些矩阵。
