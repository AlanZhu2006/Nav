日期：2026-09-07（Asia/Shanghai）\
对象：当前 GEM / 原 CEC 论文与研究代码。\
状态：深度文献核对、内部证据复盘和最小验证设计已完成；尚未运行这里提出的新定位或闭环实验。

## 一、结论先行

**有进一步提升空间，但不能靠“加一个 learned head”“改称双专家”或增加 certificate 阈值来兑现。**

目前最可靠的贡献是：把真实在线、因果单目视觉历史转为可查询的几何记忆，在不训练局部策略、不提供运行时目标角色或外部位姿的条件下，改善后续 Revisit。已有跨数据集、跨 controller 和第三目标的闭环证据；这不是仅靠漂亮叙事成立的结果。

这次文献核对也明确了边界：持久几何、外观与几何记忆、双读出、图像查询定位、自认证、固定容量、记忆服务既有局部策略，都各有先例。因此，“这些词组合在一起”不足以单独承担原创性。

**唯一优先研究假设：把“从 top-8 选一张图独立定位”，推进为“在同一因果几何状态中，对固定 top-8 的多帧证据做联合目标关系读出”。先验证信息是否有额外价值，再决定是否需要学习。**

希望获得的实质新能力不是在已接近饱和的 Revisit 上多救一个样本，而是：

> 单张历史帧不足以可靠定位时，分布在真实历史中的证据能否共同支持目标关系，同时保住无支持查询的行为和冻结 controller 接口？

这是待验证的研究问题，不是今晚已经实现的新贡献。多视图定位本身也不新；如果只把现成模型接起来而没有新能力、明确成本收益或针对因果状态的技术处理，就仍然属于模块替换。

当前投稿稿件保持 GEM 主线；不等待新学习方法成功才能收尾。新研究与现有论文证据分开记录。

## 三、最相关工作：哪些概念已经被做过

下面比较任务与接口，不把不同 benchmark 的公开 SR 与我们的自构协议横向相减。

| 工作与原始来源 | 已有内容 | 与 GEM 真正相关的边界 |
|---|---|---|
| [MemoNav，CVPR 2024](https://arxiv.org/html/2402.19161v2) | RGB-D panorama、在线视觉拓扑记忆、current/goal 两个 decoder、多目标重访；补充材料有100-node queue | 双读出、长短记忆和固定容量不能泛称首创；其策略经学习，不是将新的独立几何记忆接入冻结局部策略 |
| [CUT3R，CVPR 2025](https://cut3r.github.io/) | RGB 流更新 persistent state，并可用虚拟相机查询结构 | “流式几何状态可查询”已有先例；不等同于因果历史中的未知目标图定位及闭环导航 |
| [EAGLE，AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/37251) | 外观/几何 episodic memory 与 VGGT 支持 Ego4D 2D–3D visual query localization | “几何 episodic memory”名称和概念不是空白；其评测不是我们的机器人控制闭环 |
| [AnyImageNav，2026](https://arxiv.org/html/2604.05351v1) | 目标图几何查询、历史图像、注册自认证与近目标定位 | §3.1 输入 RGB、depth、pose；不能把 geometric query/self-certification 当作我们的独创 |
| [IGL-Nav，ICCV 2025](https://arxiv.org/html/2508.00823v1) | 在线增量3DGS、目标定位、地图探索/FMM导航 | §3.1 是 posed RGB-D；不能根据摘要中的 monocular prediction 把其输入误读成纯RGB |
| [SSMG-Nav，ICRA 2026](https://arxiv.org/html/2603.01813v1) | 持久空间/语义记忆、连续目标、路线读出，既有PointNav执行 | 仿真输入RGB/depth/pose；“记忆＋现有局部策略”已有很直接的先例 |
| [VTM-Nav，2026年7月v2](https://arxiv.org/html/2607.14514v2) | 跨独立episode的自采视觉拓扑经验、固定VLM/controller、重定位和目标检索 | 使用RGB-D，具体位置估计来源仍需实现核查；不能自行写成pose-free，也不是连续物理轨迹协议 |
| [MASt3R-SLAM，CVPR 2025](https://arxiv.org/abs/2412.12392) | 单目3D先验、相机跟踪、匹配、回环与全局优化 | 单目重定位/历史几何本身不是新问题；GEM应解释为何一个较小控制接口已足够服务其目标任务 |

**研究判断：最好的定位不是“我们发明了几何记忆”，而是明确说明我们怎样让因果单目几何成为冻结策略可用的 episodic memory，并用受控实验说明哪些信息和计算确实必要。**

不能只突出“不使用传感器深度”，却忽略其他方法在探索、长期路线、STOP或复杂目标上的不同能力。输入约束与任务能力要分别比较。

## 四、为什么学习此前没有带来稳定改善

### 4.1 最新小模型不是“完全没有用几何”，也不是普通一个 MLP

实际实现是冻结 DINO patch、两层 cross-attention，再回归 anchor-local 平面位置；几何臂额外输入真实历史 XYZ。训练103 pairs/32 scenes，验证20 pairs/8 scenes，三种子。

验证平均位置误差的种子平均：视觉1.0704m，视觉＋XYZ1.0396m；训练误差约0.09–0.14m。旧冻结GCT参考为0.4189m；finite-PnP为0.2898m，但仅19/20有效，不能隐去分母。见 [完整实验](ANCHOR_RELATION_GEOMETRY_RESULT_20260907.md)。

直接观察是：该表示和监督下存在明显泛化差距。数据少、几何预训练不足、特征分辨率、局部坐标监督与实际控制目标不一致，都可能有影响；本实验没有隔离哪一个是主因，不能只凭差距断言“数据不够”或“模型一定学不了”。

### 4.2 文献中成功的学习路线，实际上学了什么

| 方法 | 学习对象及推理结构 | 对本项目的启示 |
|---|---|---|
| [Reloc3r，CVPR 2025](https://arxiv.org/html/2412.08376v2) | 大规模几何预训练后预测相对旋转/平移方向；多个已知位姿参考通过motion averaging定位。论文约800万posed pairs | 能泛化的相对回归存在，但不为103对样本从头学习米制偏移背书；共线退化不能忽略 |
| [RoMa v2，2025](https://arxiv.org/html/2511.15706v1) | 预训练图像特征＋密集对应、置信度/协方差；输出匹配而非历史坐标 | 能单独测试匹配是否是瓶颈；仍需几何求解，换matcher本身不是新贡献 |
| [MASt3R，ECCV 2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/09080.pdf) | 学习pointmap与局部对应；预训练几何不是仅在DINO特征后加XYZ | 可以复用几何先验，但不能假定网络输出尺度自动等同于历史状态尺度 |
| [FastForward，ICLR 2026](https://arxiv.org/html/2510.00978v2) | 多个posed历史视图的features＋ray encoding，固定feature预算，预测query 3D再PnP；利用预训练encoder/decoder | 最贴近统一历史关系读出，但也直接限制“历史tokens＋query decoder”本身的新意 |
| [GLACE，CVPR 2024](https://github.com/cvg/glace) | 预训练特征＋逐场景坐标head，reprojection监督，PnP定位 | 好的小head常承担场景特定建图，不是陌生场景零适配 |
| [ACE-G，ICCV 2025](https://github.com/nianticspatial/ace-g) | 通用回归器与scene-specific map code分开；新场景仍需优化map code | “改善泛化”不等于没有新场景适配，也不等于去掉几何solver |

FastForward 的补充实验使用过手机实时SLAM产生、未后处理的 mapping poses，因此不能把“支持不精确位姿”泛称为我们的新意。但这种证据也不证明它在 LingBot 的因果误差分布中同样有效。其[官方项目](https://nianticspatial.github.io/fastforward/)确认会议归属；截至本次查询未确认官方代码/权重发布，不把它写成今晚能够直接加载的模型。

Reloc3r 的[官方仓库](https://github.com/ffrivera0/reloc3r)提供预训练权重。RoMa v2 的[官方仓库](https://github.com/Parskatt/RoMaV2)也提供加载接口；采用前需核对模型及依赖许可证，不把仓库公开等同于无限制部署。

**因此，学习若继续，目标应是利用已有几何预训练学习/读取对应关系，而不是再训一个候选分数或让小head从有限样本重学几何。PnP是否保留不是评判研究是否优雅的标准。**

### 4.3 不要把已做实验重新包装为新建议

- top-K候选链已经给出18/40 vs18/40；不能再提扩大K作为默认方向。
- CDEC候选top-1提高却降低actionable accepts；不能用候选AUC替代定位和控制指标。
- Pi3X连续当前状态对照已经做过，三臂小闭环均4/4。它改善部分路径和方向长尾，但不是新的SR提升；两个明显路程收益来自同一scene。
- query不改变stream状态、历史深度写入缓存已经测试过；扩大测量是补证，不是又一个新机制。
- metric distance没有显示胜过固定bearing；共同比例尺度与相对漂移、路线结构不同。
- 长程route-tangent的14/23停止属于新增相邻运动估计链，不能当作原LingBot stream的14次漂移失败。

参见 [Pi3X闭环](PI3X_SHARED_STATE_CLOSEDLOOP_RESULT_20260906.md)、[总账中的长程更正](OVERNIGHT_PROJECT_AUDIT_AND_REFACTOR_20260906.md)。

## 五、首选方向：固定候选集合内的联合几何关系读出

### 5.1 与当前方法的真正区别

当前：

~~~text
固定 top-8
  → 局部匹配排序
  → 只对最高候选做一次 PnP
  → 验证目标位姿
  → 与连续当前状态组合
  → 2.5m bearing → frozen policy
~~~

拟研究：

~~~text
完全相同的 top-8 + 同一份因果历史几何
  → 在同一局部参考系联合解释多帧观测
  → 输出目标相对历史的几何关系及其证据
  → 与原连续当前状态解析组合
  → 原 bearing / policy 接口
~~~

不新增目标角色输入，不新增planner，不让goal写入历史，不让查询网络重新估计当前机器人状态。候选数、输入图像和最终PointGoal半径都不变。

这不是“多个expert投票”，也不是“某帧不过就依次换帧”。区别是：多个观察约束同一个目标几何关系；是否值得做，取决于能否带来单帧读出没有的有效支持。

### 5.2 一个清楚但不冒充原创定理的表达

令 \(T_{Mh}\) 为历史anchor到流坐标的变换，\(T_{Mt}\) 为当前相机到流坐标的变换。读出器返回目标在anchor局部坐标的关系 \(T_{hG}\)。在一致的单位与相机约定下，

\[
u_t =
\operatorname{trans}\!\left(T_{Mt}^{-1}T_{Mh}\widehat T_{hG}\right),
\qquad
b_t=\frac{P u_t}{\|P u_t\|},
\qquad
g_t^{policy}=2.5b_t .
\]

\(P\) 表示相机坐标到机器人水平平面的投影。这个组合公式已有实现，是标准几何关系，不是新增理论贡献。

如果查询读出是多视图重投影求解，可以写成同一目标位姿对一组历史对应的联合解释：

\[
\widehat T_{hG}
=\arg\min_T
\sum_{i\in\mathcal K}\sum_j w_{ij}
\,\varrho\!\left(
\left\|\pi(K_G T^{-1} X_{ij}^{h})-q_{ij}^{G}\right\|^2
\right).
\]

这里的 \(X_{ij}^{h}\) 全部在同一历史局部坐标系，\(q_{ij}^{G}\) 是目标图的对应位置；\(\varrho\) 是稳健代价。公式是概念定义，并非已经指定新的loss、权重或solver。

多帧看到同一目标关键点时，对应项相关，不能重复计数后宣称有更多独立证据。各帧单目几何也可能不一致；联合求解并不天然比选择最好一帧更强。

### 5.3 为什么它比继续单anchor位置回归更值得先检验

1. 它检验的是额外几何信息能否带来新能力，而不是只换网络容量。
2. 原方法已经算过top-8匹配，但最终只让一个候选参与PnP；有一个明确的信息使用差别可控制。
3. 现成多参考定位模型为结构提供先例，不必从100多对数据重学整套几何。
4. 它继续复用连续状态和双读出，不把系统变成另一个全局planner。

这些是选择实验的理由，不是预言改善。

### 5.4 为什么不能直接宣布这是创新

FastForward、Reloc3r、传统多视图定位都已经使用多参考信息。仅把其中一个接到LingBot后面，没有资格声称发明新的多视图定位。

升级为论文方法至少需要出现以下一种实质证据：

- 在真实因果单目状态、固定历史输入下，获得原单帧方案无法可靠处理的部分支持查询；
- 有针对该状态误差与查询时序的技术处理，并用相同模型/数据对照隔离其作用；
- 在保住控制效用的同时，显著减少记忆、首次查询或累计计算成本；这必须是实测能力，不是“模块数量变少”。

若没有这些变化，就把结果作为替换消融，保留当前GEM，而不是继续换名字。

## 七、最小验证顺序：先回答问题，再决定训练

### 第一步：本机数据资格检查，无导航

限定train40及其内部开发划分。先盘点每个query的：

- 真实因果历史、候选时间、RGB与姿态/深度绑定；
- 同一top-8内可用几何、不同相机中心及非退化基线；
- 历史几何是否来自同一流单位，是否缺少某个anchor；
- 强支持、部分支持、无匹配的独立评价标签及其来源。

GT只用于离线分层与误差评价，不进入候选选择或模型forward。缺少几何时如需提取，应单独统计成本；不能以GT depth补齐后声称单目。

### 第二步：固定状态的三臂定位对照

| 臂 | 做什么 | 回答的问题 |
|---|---|---|
| A：当前GEM | 原排序、单候选PnP，原几何 | 当前参照 |
| B：经典联合几何 | 完全相同top-8，使用多参考对应共同解释目标位姿 | 收益是否只是多视图信息，而不是新网络 |
| C：预训练Reloc3r读出 | 完全相同top-8，用相对方向/旋转与参考姿态估计目标关系 | 现成几何预训练是否能够减少稀疏读出的匹配/历史深度/PnP链条 |

这是方法包的开发对照；B/C本身不天然共享A的证书语义，不能搬用A的accept标签给新位姿授权。首阶段只测定位与证据，不让新的valid pose直接控制机器人。

C有重要约束：一张anchor图的平移方向不能确定目标距离；没有至少两个有用、非退化参考时，不能随意指定距离后当成完整目标位姿。可先测纯pair相对角度，再判断是否满足多参考定位条件。

B对相关点去重/限权，至少报告不同query关键点和不同参考视图的贡献。不能让重复观测把inlier数量人为放大。

全部报告：

- query级位置误差、当前坐标下的endpoint bearing误差及尾部；
- 有效覆盖与未输出比例，不能只报告模型愿意输出的成功子集；
- 部分支持、无支持及正常成功query是否被改坏；
- 同一硬件下的feature写入、首次读出、缓存读出、总查询wall time、存储和GPU峰值；
- 场景级统计，而不是把几百个replans当成独立样本。

不要把geodesic第一段方向差误写成目标定位误差。已消费案例用于开发，不作为新的confirmation。

### 第三步：根据结果决定去留

- **B/C都没有可靠改善：** 不扩训练、不进HPC；不能为了新颖性继续堆结构。
- **B有效、C无效：** 额外信息有效，但统一learned读出尚未兑现。可研究几何条件读出，不宣布模型已经替代传统几何。
- **C有效且不输B：** 才有理由研究更小的蒸馏/适配模块；原始现成模型作为必须保留的强baseline。
- **只改善离线角度或一两个已知失败：** 不升级主方法；先小闭环，兼含原成功、失败与无支持query。
- **只提高SR却使无支持干预/成本大幅恶化：** 不是无条件升级，应报告真实权衡。

小闭环固定A历史、controller、随机种子、执行预算和2.5m接口，同机配对。新读出的授权需重新绑定实际输出证据，不复制旧证书。确认阶段的非劣效/优势目标、样本数与统计方案应在读取其结果前另行确定。

本轮没有宣称这些测试已提交或运行，也不承诺它们只需几十分钟；模型权重、几何提取与依赖预检成本尚未实测。

### 第四步：如果确实需要训练，改变监督职责

训练只负责历史到目标的关系；DINO寻址、连续当前状态、dense readout和局部策略先保持冻结。

优先复用成熟几何预训练，监督对应、重投影或目标关系的一致性，而非重新学习Novel/Revisit类别。训练样本应包含真实有支持但被旧certificate拒绝的情况，不能只蒸馏teacher接受的简单正样本。

可利用pt1专家轨迹构建训练关系，但需要按场景划分；专家轨迹训练不等于正式实验使用actual-online history。若监督需要GT深度/pose，只能用于训练与评分，不得混入部署输入。

仅仅改loss名字、再加一个方向项并不能解决问题——现有小模型已经有方向损失。先证明表示与预训练带来可泛化信息，再决定更长训练。

## 八、另外两条路为什么不是本轮P0

### 共享几何的成本与长期保存

写入时保存主流历史深度，已经把4-query小闭环的首次证书阶段中位数从20.330s降到0.126s；两臂Revisit仍3/4。该计时不含外部DINO、NavDP、通信和执行；不能写成系统端到端延迟。

它值得进入正确版本的实现与成本说明，但单纯缓存不是新定位算法。未来若做全局预算下的记忆压缩，应与FIFO、均匀采样等比较；MemoNav已有容量限制，不能只因采用固定长度就称创新。见 [现有小闭环](CEC_STREAM_DEPTH_CLOSED_LOOP_STATUS_20260907.md)。

### 空间长程导航

20–30m同层压力集，endpoint 0/23、route tangent4/23，仍未形成正式成功结论；它使用受控causal survey，不是主表actual NavDP-A历史。

长程可能涉及定位、路线拓扑、跟踪与controller接口。增加联合目标定位不能凭空给出绕墙路线。应先完成既有长程分解，而不是将它作为今晚新读出方案必然解决的问题。当前论文的episode记忆贡献不必被强行升级为完整lifelong路线规划。

## 九、对当前论文的实际建议

保留标题、Abstract和Introduction的主线。不把“certificate通过阈值”放大成唯一贡献，也不因训练free而贬低完整系统结果。

更有说服力的讲法是：

> GEM makes causal monocular experience geometrically queryable for a frozen navigation policy. The same stream supports local depth estimation and the recall of previously observed goals.

这段是叙事建议，不是已应用改稿；它不新增“first”、更高SR或新学习机制的claim。当前文章中的query-derived状态隔离、几何来源、两类读出与跨controller结果应共同支持这句话。

若上述新研究成功，再补一句它实际获得的能力，例如在分散支持下的定位或更低累计查询成本；在没有结果前，不写“统一learned memory已经替代传统CV”。

**最终优先级：**

1. 完成现有稿件和既定SPL收尾，保护已成立结果。
2. 先做固定top-8的联合关系读出资格检查与本机定位对照。
3. 只有新信息和闭环价值兑现，才训练、扩样或改主方法。
