# 仿真最小修复与论文重跑范围

日期：2026-09-08。当前是实现/证据范围判断，不是新 SR 报告；不修改已有论文数字。

## 1. 最小方案不是换一个更复杂的 controller

保留 frozen NavDP、CEC、2.5 m bearing、现有相机和控制预算，只分清三个接口：

`标准 RGB/对齐的单目深度 → frozen NavDP 参考轨迹 → 有限步长跟踪 → 环境碰撞响应`

- 输入转换负责通道与栅格，不负责决定路线。
- 跟踪器只根据机器人状态和参考轨迹给出运动请求；零参考不自行推进。
- 环境负责碰撞阻挡，不把 NavMesh 交给策略作候选排序或另找路线。

新增规则来自数据/动作的定义，而不是 SR 调参：RGB 通道与输入一致、深度像素对应同一相机射线、
命令不超过所跟踪参考距离。没有新增 critic 门、证书门、恢复模型或搜索策略。
CEC 原有“不够证据则不接管”的语义和 NavDP 自带低 critic 搜索均保留，不能说整个系统没有 fallback。

本方案仍是 Habitat 运动学评估，包含标准 NavMesh 碰撞和理想状态反馈。
若要求环境也完全不用 NavMesh，就需要另行选择/校准刚体物理模型；不能靠改函数名称实现。

## 2. 各项变化不能混成一个无法归因的新 SR

| 变化 | 实现证据 | 当前验证 |
|---|---|---|
| bounded pursuit + 标准环境步进 | 已实现隔离模块，非约束命令保持旧值 | 四历史六臂完成核验；native 1/4→0/4，CEC 3/4→2/4，影响不能忽略 |
| base RGB/BGR 修正 | 真正官方 client/当前 server/实际 encoder 端到端通道测试 | 同一六臂完成；N=4 成功标签未变，不是颜色无影响证明 |
| LingBot depth 回到原 RGB 栅格 | 实际 loader 与真实缓存深度确认；不改变高度尺度 | 测试、短测与两历史八臂闭环均完成；native 0/2→1/2、CEC 1/2→1/2，不能外推总体效应 |
| 后向 PointGoal 的真实前向域适配 | 只处理已发出的后方目标；每步新 RGB，转后重新规划；raw/CEC 共用 | 四历史 16 臂完成；raw/CEC 各自 2/4→4/4，+2/−0，p=0.5；不能解释为 CEC 独有增益 |

已先完成冻结六臂；深度修复使用新的独立配对，没有中途混入。
不能因 RGB 修正后某个场景 SR 没升就保留错误通道，也不能预言每个接口修正都提高 SR。

## 3. 哪些需要重跑，哪些不需要

问题不应表述成“旧数据是否全部作废”，而是“新版本主张依赖哪一段执行”。

| 证据 | 保留旧版本结果 | 若声称代表修复后的主系统 |
|---|---|---|
| 完整 mono-A + mixed-query 主结果 | 可作为明确旧执行合约的历史结果 | 必须采集新版本真实 A，再构造查询并对 native/raw/CEC 配对；不能直接复用旧 A 冒充新端到端系统 |
| Table I NavDP × HM3D/MP3D | 旧配对事实不自动变假；颜色覆盖须查原冻结 bundle | 更新执行/输入后的 controller 内 native/CEC 都要跑；不只跑 CEC |
| Table I ViNT | 单独核对当前实际解码和预处理，已确认同类 BGR 问题；仍待正式 bundle 绑定 | 同样受公共 executor 变化影响；若更新表中执行/颜色口径，需要该 controller 的配对，不能只重跑 NavDP |
| Table II 连续目标 | 旧 C\|A,B 条件结果可保留 | 新全流程必须重做有变化的 A/B 前缀；若仅复用旧前缀测 C，须继续称“给定旧前缀”的执行敏感性实验 |
| Table III 深度消融 | 已完成 SR/SPL 属于当时的输入和执行配置 | 若修复 mono 的 raster 或基线 RGB，应在同一执行版本上重跑比较臂，不能用新版 mono 横减旧 metric |
| Table IV 闭环授权消融 | 旧框架的消融仍有版本内解释 | 若用于解释新版性能，须使用新版共有 executor/输入配对；优先保留 raw/CEC 关键比较 |
| 离线 DINO、几何/PnP、证书 precision/recall | 未被执行器或 NavDP 图像转换直接改变，可保留 | 不因 executor 改动自动重算；若改变其独立输入或参考深度，再按实际依赖重算 |
| 消费过的长距离诊断、oracle、小样本支线 | 保留原始记录和明确诊断定位 | 不必把每条旧支线重跑；不能用旧控制归因解释修复版而不作桥接 |

**核心判断：如果整篇论文所有闭环表都要代表一个统一的修复版本，多数闭环比较确实需要补跑。**
不能拿 N=4 相同 SR 当作免重跑的等价证明；也没有理由重跑与修复无关的全部离线工作。

本轮进一步只读追溯了旧 HM3D full-mono 的 168 个 query 文件：28 个 CEC-Revisit 查询中，
17 个至少有一次“候选终点长度全零、critic ≥ −0.5、下一动作仍有实际移动”的记录，
相应 29 次记录的 pointgoal 均在后方。原日志未保存完整候选坐标，不能重建修复后的轨迹，
更不能把这些病例全部认作伪成功。但它排除了“可能只是今天的小测才碰到”的轻率解释。
完整逐记录收据见 `archived_fullmono_zero_endpoint_motion_v1.json`（同一诊断父目录）。

**“native 和 CEC 共用执行器”不能自动抵消这种偏差。** CEC 会发送后向 PointGoal，
而原生 ImageGoal 不经过同一坐标裁剪；本次旧日志中 native-Revisit 的相应暴露为 0/28。
因此需要测量的是“方法与执行器的交互”，而不仅是一个对所有臂相同的环境常数。
这不等于已经证明 CEC 的增益由 bug 造成；新执行合约的成对闭环才是该问题的反事实检验。

## 4. 最省算力且不混版本的顺序

1. 本机接口桥接已完成：执行/颜色、depth-raster、后向 PointGoal 配对，以及两条非接管请求前缀等价检查；全部成功/失败视频保存。
2. 固定一个候选主配置，不再边看主表边加修复。
3. 先补一个完整 mono-A 的核心 mixed-role population，native/raw/CEC 同机配对；
   原场景/种子/构造门可以保留，历史必须来自新版真实 rollout，构造人数的变化单独报告。
4. 核心结论成立后，再补 Table I 的其他域/controller 和必要的深度/授权/连续目标消融。
   不以更换控制器扩大主贡献，也不新增一轮无关长训。

本轮没有提交这些正式任务；这里只确定依赖与顺序。
各阶段已完成结果、验证与未决事项见 `HABITAT_MINIMAL_EXECUTION_AUDIT_20260908.md`。

## 5. 后向输入的设计边界

把零参考改成 hold 是执行正确性修复，但不会自动把后向目标变成模型能表达的目标。
应明确 NavDP 的前向 PointGoal 输入域，不能把负 forward 的裁剪当成保持了原 bearing。
若后续采用真实朝向调整，其定位应是 controller 的目标接口适配，不是第三个专家或失败回退：

- 方向只能来自收到的目标请求，不来自 evaluator 的目标或最短路；
- 转动消耗真实动作预算，每步更新实际 RGB，结束后重新规划；
- 同一 PointGoal 适配必须用于 raw memory 和 CEC，不能只给 CEC 加新能力；
- 不把零轨迹解释为已经到达，也不能用转身前的旧 RGB/轨迹伪装新视角；
- 纯转身对 LingBot 平移估计和局部可行性的影响仍须独立验证。

此前 Bullet 四历史对照只支持它能救回两个零轨迹病例，同时出现一个后续接触失稳。
本轮随后在同一标准 Habitat 执行接口上完成独立四历史 off/on：raw/CEC 各自 2/4→4/4。
这不是择优拼接 Bullet 和 Habitat；两套结果分开保留，最早六臂/深度臂均未启用此适配。
详见 `HABITAT_FRONT_GOAL_BRIDGE_RESULT_20260908.md`。

纯转动问题未被掩盖：本轮真实平移为 0，LingBot 却估出约 0.095–0.373 m 平移，
估计 yaw 与实际相差约 1.46–6.58°。四例仍恢复到达，不代表长程漂移或机体安全已经解决。
真实 non-takeover 短测也完成，两条 Novel 查询 64 动作前缀与 native 完全一致；
该短测只关闭请求链问题，不替代 full-mono mixed-role 重跑。

### 采用该适配时必须更新的描述

后向目标的显式 yaw 动作由低层适配器执行，不是 diffusion decoder 生成的轨迹。
“NavDP 权重冻结”仍成立；“全部运动都直接来自 NavDP 输出”则不能原样沿用。
它不是新的检索专家、目标方向源或地图规划器，但确实是控制接口的一部分，不能藏在实现脚注里
再把收益全部归给记忆定位。本机四历史 raw/CEC 共用 off/on 对照正是为分离这层作用。

同样，Revisit 上接口恢复不自动证明 Novel 更安全。证书一旦错误接管，正确执行一个错误方向
仍可能造成干扰。除了本机真实拒绝分支的短测，修复版主评测必须保留 mixed-role native/raw/CEC；
不能只凭已有高支持 Revisit 的上升就替换全部论文表格。
