## 清理与恢复合约

1. 显式目标 → 文件清单、大小、mtime、inode。
2. CPU 作业打包到 scratch 的 `verified_archives/`，记录每个原文件 SHA256。
3. 完整顺序回读压缩包、核对每个文件，再核对原目录没有改变。
4. 持久写入归档收据后，才删除该确切 runtime buffer 的散文件。
5. 登录节点将已验证压缩包转存到 `/archive/yz11502/nav_runtime_buffers_20260909/`。
6. 再次核对完整压缩包 SHA256，更新恢复指针，才删除 scratch 中重复的压缩包。

步骤 4 释放文件数量；步骤 6 才将归档所占字节也移出 scratch。
这不是永久销毁旧图像；可按原路径恢复。归档受站点 `/archive` 保留政策约束，
不是对永久备份的承诺。

每个原 buffer 的父目录保留 `buffer.ARCHIVED_20260909.json`，里面有归档路径、
哈希、删除数量和确切恢复命令。集中收据：

`/scratch/yz11502/Research/Nav-axis-uturn-results/maintenance/cold_buffers_20260909/receipts_stage_v2/`

原始 code、targets 和失败日志保留；没有覆盖旧清理记录。
