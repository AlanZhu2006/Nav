# MP3D Table-1 new-query replication protocol

## Scientific scope

This is the second-dataset half of the conference Table 1. It tests the same
four rows as HM3D (`NavDP`, `NavDP+CEC`, `ViNT`, `ViNT+CEC`) on role-hidden
Novel/Revisit queries. The primary estimands remain CEC-minus-native within
each controller. Absolute NavDP-versus-ViNT differences are contextual because
their native action and observation interfaces differ.

No untouched official MP3D scene remains: train40, development20, blind16, and
Final14 consume all 90 scenes. This experiment must therefore be described as
a **controlled reused-scene/history, new-query replication**, not fresh-scene
generalization.

## Frozen source population

- Source data: immutable Fresh160 20-scene manifest, first two episodes per
  scene by manifest order (40 histories before Goal-A attrition).
- History: the actual causal full-monocular Goal-A trace generated by the
  sealed MDTEC composition run; every source trace is included before checking
  Goal-A eligibility.
- Construction never opens the previous Goal-B arm metrics, plans, summary, or
  success values.
- Each successful, sufficiently long Goal-A trace is re-rendered and every RGB
  frame must reproduce its trace SHA-256. A mismatch is infrastructure failure,
  not scientific attrition.

## New query contract

Every eligible history attempts exactly one pair:

- unsupported Novel: maximum online-A co-visibility `<0.10`;
- standard Revisit: co-visibility in `[0.55,0.90]`;
- query geodesic: `2--9 m`;
- Novel direction: frozen preferred front/side/rear stratum, followed by an
  identity-bound deterministic fallback through the remaining strata;
- the source Fresh160 Goal-B is forbidden by both JPEG SHA-256 and pose+yaw
  identity, for both newly rendered roles.

Runtime never receives the Novel/Revisit role. Construction reads no query
navigation outcome.

## Prospective power gate

All constructible histories are retained; none may be selected by downstream
performance. Formal controller evaluation is authorized only if construction
and the independent verifier obtain:

- at least 20 histories;
- at least 12 scene clusters;
- at least 4 Novel queries in each direction stratum.

Failure of this gate is a valid underpowered construction result and stops the
formal rollout. Thresholds and population may not be repaired after outcomes.

## Formal runtime, if authorized

- same frozen benchmark manifest for all four rows;
- full-monocular causal depth for NavDP and the same controller-specific native
  inputs already frozen in the HM3D Table-1 protocol;
- 1 m success radius, 600-step budget, balanced within-controller arm order;
- NavDP reject: exact unchanged native ImageGoal request;
- ViNT accept: bounded physical bearing turns with fresh observations, then
  unchanged ViNT on the verified historical anchor ImageGoal;
- ViNT reject: exact native ViNT ImageGoal control;
- same episode-level logs, SR/SPL/path/final-distance statistics, paired
  gain/loss, exact McNemar, scene-cluster bootstrap CI, and independent raw-file
  verification as HM3D.

Construction-only jobs produce no controller outcome. Formal jobs are a
separate, verifier-gated submission.
