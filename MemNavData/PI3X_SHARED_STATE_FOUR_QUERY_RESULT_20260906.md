## 3. Novel 接管到底意味着什么

原构造标记为 `unsupported_novel`，但最大 online-A 共视为 **0.07903**，不是零。原选定 anchor 为第 8 帧，其构造共视约 0.07330。弱共视的语义需与绝对无历史支持区分。

原运行中：

- Pi3X 接受 42/51 个计划；
- CEC 接受 34 个计划；
- Pi3X 与 CEC 最终均成功，native 与 raw fixed 在该 Novel 上失败。

因此，本例不能简单称为“Pi3X 把 Novel 误判成 Revisit，所以导航错误”。Role 标签不是模型运行输入，也不是相对定位对错的直接标签。低于 benchmark 的构造共视阈值，仍可能存在可用的局部几何。

本轮准确的说法是：在一个构造上弱支持、原方法实际接管的 Novel query 中，连续状态组合降低了目标方位误差。它不证明开放集授权普遍可靠，也不说明所有 Novel 都应该干预；本轮没有测试新的授权决策。

## 4. 保持了哪些条件

三种读出和两模型坐标对齐完全沿用上轮，不重选阈值：

```text
s_t = ||t_L(a+8) − t_L(a−8)|| / ||t_Pt(a+8) − t_Pt(a−8)||
g_L,t = t_L(a) + s_t R_L(a) R_Pt(a)^T [t_Pt(goal) − t_Pt(a)]
b_t = normalize(horizontal(R_L(t)^T [g_L,t − t_L(t)]))
```

动态目标使用每次的 `g_L,t`，固定目标使用首次的 `g_L,0`；当前状态总是继续更新。这里的 `s_t` 是两个单目重建的单位比，不是 GT 米制尺度。

- 公共支持分别是 `[71,79,87]` 与 `[0,8,16]`，均早于 query；没有使用未来帧。
- 首次单位比分别为 0.097903 和 0.130880；没有使用传感器深度、GT pose 或相机高度恢复米。
- LingBot：S=8、window=32、max_frame_num=2048、SDPA、BF16；两条都沿原 A-prefix + 600-step 合约使用 25 px flow tier。
- Pi3X：原首次 anchor、原 b16 抽帧方式、相同预训练权重与 BF16；所有重规划时刻都执行。
- 复用上轮提取脚本和逐字节相同的评分脚本。新增 wrapper 只压缩 stdout 中的最终 JSON，避免传输截断，不改变模型计算。
- 下游三读出使用同一份 Pi3X 输出和同一份连续状态，不重新采样 NavDP，不改 2.5 m 接口。

旧 H100 与本机 RTX 4090 未逐位复现。四个案例中原/本机 >90° 次数分别为 11/10、2/2、3/3、4/5；合计恰好均为 20，不代表逐时刻错误相同。本轮结论以本机同观测的读出对照为依据。

## 6. 对下一步的实际影响

### 已得到更具体的改进方向

不是直接宣布“Pi3X 比 CEC 好”，而是发现此前 learned 替换把两种不同任务绑在了一次稀疏 batch 重建里：持续定位当前状态，以及估计目标相对历史的关系。连续当前状态与稀疏目标定位分离后，四条已知异常上的方向读出均改善。

若继续 learned 路线，更有根据的职责是估计目标相对已寻址历史的关系；连续定位复用现有状态。没有理由现在重新训练一个同时承担寻址、定位、授权和路线规划的大 decoder。

### 暂时不能写成结论的内容

- 本轮只覆盖已知异常，没有检查其余正常 query 是否被改坏。
- 四条中原 Pi3X 已有三条成功；降低角误差不自动增加 SR。
- 固定目标不是一致优胜；减少查询次数与持续更新精度有待独立权衡，不能直接宣称无损加速。
- 新读出不能无条件继承旧 proof 的可靠性；授权需对应最终实际使用的方向，而非另一个联合重建的方向。
- endpoint bearing 准确不等于有绕障路线，本轮不证明空间长程问题或所有 LingBot 漂移已经解决。

### 下一步最小闭环问题

优先检验连续状态分工本身：保留动态目标关系，在本机少量、共享 A 历史的闭环开发对照中，与原 Pi3X 和 CEC 比较；案例必须兼含原成功与失败，核查新增方向与授权的一致性。固定目标只作为随后独立的推理频次问题，不预先认定为主方法。

本轮没有启动该闭环或长训。若后续 SR 未改善，仍需把方位稳定性结果与控制收益分开，不能用本轮 0/143 的方向长尾替代新的导航证据。
