# 冻结 NavDP 的 point-token 可操纵性传递函数

日期：2026-08-08

代码：`scratchpad/probe_directional_prompting.py`、`probe_backward_cone.py`、
`probe_heading_vs_chord.py`（本地探针，未提交）

协议：post-A goal-switch 状态；1 次 native `imagegoal_step`（唯一一次 FIFO
append）后，对同一 FIFO 做 read-only `mixgoal_resample`，注入半径 2 m、指定
方向的合成 point token；每次 16 candidates；`memory_mutated=false` 逐次断言。
2 场景 6 episode（饱和扫描用 2 episode）。**零 GT 输入**（GT 仅用于进展标签）。

## 1. 主结果：方向多样性可被"提示"召回

| Episode | native R / 正进展 | 8 方向 union R / 正进展 | union 最佳进展 |
|---|---|---|---:|
| 17D/ep0 | 0.97 / 0% | 0.57 / 40% | **+2.59 m** |
| 1L/ep1 | 0.93 / 0% | 0.59 / 30% | **+1.23 m** |
| 17D/ep1 | 0.98 / 0% | 0.45 / 0% | −0.15 m |
| 1L/ep2（18.6 m） | 0.998 / 0% | 0.57 / 0% | −0.90 m |

塌缩的 4 条中 2 条被唤出真实前进模态。**结论：mode collapse 至少一半是
"没被问到"而非"不存在"**，且召回不需要物理转身——read-only token 注入即可。
未被唤醒的两条，其真实 bearing 分别为 186° / 191°，落在下节的死区。

## 2. 传递函数（每个 plan，单位：相对当前朝向的度）

| 请求 | 实现（弦/后半段行进方向一致） | 候选存活 | 轨迹长度 |
|---:|---:|---:|---:|
| 0° | ~0° | 16/16 | 2.0–2.2 m |
| ±60° | ±53–58°（忠实） | 16/16 | 2.2 m |
| **±90°** | **±63–76°（峰值）** | 16/16 | 2.3–2.8 m |
| ±120° | ±55–71°（开始回退） | 15–16/16 | 2.0 m |
| ±150° | 崩塌：extent 0.5–0.8 m | 9–14/16 存活，0 条通过后半段位移检验 | 0.7 m |
| **165°–195°** | **零输出** | **0/16**（extent 恒为 0.000） | 0 |
| ±240°/±270° | 反向侧可达 ~−100° | 16/16 | 2.1–2.6 m |

三点已验证的解释边界：

1. **零输出是策略行为，不是探针几何伪影**：165–195° 上 16/16 candidate 的
   extent 恰为 0.000，而非端点落在不可导航区（后者会有非零 extent）。
2. **弦没有低估转角**：后半段位移方向 ≈ 弦方向（如 +90°：62.8 vs 64.6），
   且 path length ≈ 端点距离（2.69 vs 2.34）——轨迹近乎直线而非圆弧，
   不存在"弦=转角一半"的折算。
3. waypoint 第三通道（文档称 heading）数值与行进方向系统性不符
   （+90° 请求时仅 +7.5°），语义存疑；本文结论不依赖它。

## 3. 对 GLP 方向层的部署含义

- **|Δbearing| ≤ 60°**：直接请求该方向，忠实执行；
- **60° < |Δ| ≤ ~100°**：请求 ~±90–105°（峰值区），单 plan 可得 ~65–100°；
- **|Δ| > 100°**：分多个 plan 迭代（每 plan commit 8 frames，约 65–90°/plan），
  **绝不请求 165°–195°**；180° 掉头 ≈ 2–3 个 plan；
- 物理原地旋转只在迭代 token 转向不可行时使用——这同时避开了单目几何在
  纯旋转（无视差）下的平移不可观问题（见 LingBot 漂移讨论）。
- token 扩增必须配选择层：union 在 native 本已良好的 episode 上会稀释正进展
  比例（错误方向候选混入），单独 union 不是策略。

## 4. 与既有结果的关系

- 与 oracle bearing 臂（`b2_turned` 4/6、executed+bearing 4/5）互补：那里证明
  "方向信息有价值"，这里证明"方向可以被 read-only 注入部分兑现"；
- 与 mode-collapse 诊断（R≈0.98–0.99）互补：R 可被提示降到 ~0.5；
- 未解决：165–195° 死区内的目标仍需物理转向或多 plan 绕行，这是 2 条未被
  唤醒 episode 的直接原因。

## 5. 闭环验证：可部署的 bearing 执行层（2026-08-08）

臂 `b2_token_steer`（`eval_3leg_symmetry_habitat.py`）：与 `b2_turned` 使用
**完全相同的 oracle 目标方向**，但执行方式从"瞬移改 yaw"（不可部署）换成
**迭代 mixed image+point step**——每个 plan 都是真实决策（stepping 端点，
FIFO 正常前进一次），执行 `exec_horizon` 帧，直到残差 ≤20° 或用尽 plan 预算，
随后交回 native ImageGoal。

| Episode | arrival | turned（瞬移/oracle） | tokP3（可部署，≤3 plan） | tokP10（≤10 plan） |
|---|---|---|---|---|
| 17D/ep0 | 8.06 | **1.00** | **1.00** | **1.00** |
| 17D/ep1 | **1.00** | **0.99** | **0.97** | **0.99** |
| 17D/ep2 | 5.21 | **0.99** | **0.97** | **0.97** |
| 1LX/ep0 | 2.49 | **0.99** | 2.49 | 2.49 |
| 1LX/ep1（死区 186°） | 4.05 | 5.76 | 11.21 | 7.60 |
| 1LX/ep2（死区 191°） | 9.06 | 8.77 | 15.47 | 9.47 |
| **SR** | **1/6** | **4/6** | **3/6** | **3/6** |

配对（vs arrival）：turned +3/−0；tokP3 +2/−0；tokP10 +2/−0。

结论：

1. **可部署执行层兑现了 oracle 瞬移三个增益中的两个**，且零损失。代价很小
   （平均额外路径 0.75 m / 1.12 m）。每 plan 实际转约 22°（8 帧执行量，
   不是整条 24-waypoint 轨迹的转角）。
2. **未完成的转向比不转更糟**：死区两条在 P3 预算下只转了一半
   （残差 −80°/−101°），final distance 从 4.05/9.06 恶化到 11.21/15.47；
   把预算提到 P10 后残差收敛到 −3.7°/−5.3°，final distance 回到 7.60/9.47。
   **设计规则**：所需 plan 数 ≈ |残差|/22°，若超出 burst 预算则应 abstain，
   绝不执行部分转向。
3. 死区两条即使转向完全收敛仍未成功，而 oracle 瞬移同样失败——这两条的
   瓶颈不在 bearing。
4. `1LX/ep0` 是 token 未兑现 teleport 增益的唯一一条：转向已收敛
   （残差 −16.9°）但结果与 baseline 逐位相同（2.49），说明转向过程中的
   ~0.75 m 位移改变了后续状态；属于此前多次观察到的闭环混沌敏感性。
