# MemNav 项目最新状态

更新：2026-08-10（CST）

本文是当前 canonical 快照，只分为 **NOVEL、REVISIT、X-NAVDP** 三块。
完整实验细节、协议偏差与工件 SHA 见 `STATUS_20260810_FULL.md`。

**为什么前几天研究 NOVEL/X，而现在重心回到 REVISIT**

- REVISIT 已有项目最硬的方法结果：geometry memory 两次 N=40 都显著增益、零配对损失。
- 项目上限开始被 NOVEL 限制；oracle bearing 能把 Novel-A 从 `28/40` 提到 `40/40`，
  但我们还没有可部署的 visual bearing source。
- X-NAVDP 是对“拿到 PointGoal 后，剩余失败是不是 controller 造成的”这个问题的对照；
  它有 PointGoal post-training、twin-Q 和倒车能力，所以值得完整审计。
- 归因现在已经闭合：Novel 仍没有可部署 source；X 只有局部 deep-rear 优势；REVISIT
  仍是唯一显著、oracle-free 的方法结果。因此 verified-bearing residual adapter 冻结为
  可靠 baseline；最终方法转向 RANSAC-free 的 loop/no-match expert + bearing-reliability
  expert，而不是继续替换 controller。

| 能力层 | 当前结论 |
|---|---|
| 方向从哪来 | REVISIT 有 geometry memory；NOVEL 仍缺可部署 source |
| 何时相信方向 | Geometry 门可用；learned confidence 跨场景校准仍不稳 |
| 拿到方向后怎么执行 | Mixed NavDP 仍是默认；X/MPC 有 deep-rear 能力，但没有全局 SR 优势 |

> 口径：oracle 只是机制上限，不是可部署 SR；10-scene development 和 20-scene pool 已耗尽，
> 16 blind scenes 仍未打开。不同运行的 native 绝对 SR 不能跨机混算。

## 1. NOVEL

**结论：Novel 的主要可恢复瓶颈是持续方向信息；冻结 NavDP 能执行正确局部方向，
但目前还没有可部署的 Novel 方法增益。**

### 已确立的证据

| 实验 | 结果 | 说明什么 |
|---|---|---|
| Oracle bearing N=40 | `28/40 -> 40/40`，`+12/-0`，`p=0.000488`，CI `+15~+47.5 pp` | 方向是强可恢复瓶颈；但是 oracle |
| Oracle token 执行 | 同样 `40/40`；35/40 激活、159 次执行 | 现有 token/controller 能兑现方向信息 |
| Bearing dose N=38 | 每周期/每 4 周期 `38/38`；start-only `26/38`；±30° `38/38`；±60° `25/38` | 需要可刷新的方向流；±30° 可容忍，±60° 不可接受 |
| Mode-collapse probe | 64 candidates 的 heading `R≈0.98~0.99` | 候选数多不等于方向多样 |
| Point-token transfer | ±60° 大体忠实；165~195° 为 16/16 零位移 | token 是局部转向接口，不是全向 controller |

### 可部署方向源的现状

| Source | 结果 | 判定 |
|---|---:|---|
| Goal-blind frontier | 4/5 vs 4/5 | 无净增益 |
| DINO-CLS frontier rank | 3/6 | 比 goal-blind 4/6 还差 |
| NavDP critic 跨方向选择 | oracle ±30° hit 0/9 | critic 不读 ImageGoal，不是目标方向源 |
| Diffusion score-field | 1/9，平均排名 4.56 | 等于随机 4.5 |
| Active-glance V1/V2/V3 | `20/40 -> 24/40 -> 25/40`，native `31/40` | margin/gating 减少伤害，但仍未超过 native；V1 `+2/-13, p=0.00739` |

Frontier proposal coverage 实际不差：9 条 A failures 的 486 个 states 中，
`421/486=86.6%` 至少有一个 ±30° candidate。真正缺的是
**goal-conditioned selection + confidence + takeover timing**。

现成 expert trajectory 也不能直接训 bearing：1434 个 states 中 97.5% bearing 在 ±10°，
100% 在 ±30°，模型只会学成“永远向前”。

### O1 最新结果

O1 部署输入只有**一张当前 RGB + ImageGoal**；8 yaw 只用于 yaw-balanced teacher，
不要求部署时原地转圈。

- 31 train scenes scene-OOF；
- off-axis progress 相对 camera-forward：`+0.218 m`，CI `[+0.150,+0.285]`；
- gains/losses `184/118`，positive/negative scenes `26/5`；
- goal-swap NLL contrast `+0.174`，CI `[+0.0895,+0.276]`；
- exact C8 bin 只有 `17.74%`，circular error `85.5°`。

O1 证明冻结 NavDP representation 中有**弱但真实的 goal-conditioned progress signal**；
它不是高精度 bearing solver，也还没有闭环 SR。

### 后续（已降为次级支线）

Novel 的 P1 frozen-policy state-transfer 协议保留，但不再是当前主任务：

1. 冻结 O1，不扩 head、不重训；
2. 在 61 条 train-scene Novel-B native rollouts 中收集自然/失败 states；
3. 比较 O1 direction 与 NavDP 实际 executable heading 的 1 m progress；
4. confidence 阈值已冻结为 `R>=0.346483`；
5. P1 通过后才做 selective closed loop；Novel-A 还需独立冻结验证。

## 2. REVISIT

**结论：Geometry memory 是当前唯一显著、oracle-free、闭环有效的正向方法结果；
剩余瓶颈主要是激活召回和 alias，不是候选数量。**

### 核心结果

| 实验 | 结果 | 结论 |
|---|---|---|
| 历史 HPC N=40 | joint `4/40 -> 19/40`，`+15/-0`，`p=6.10e-5` | 首个显著方法结果 |
| Deterministic R0 N=40 | joint `3/40 -> 20/40`，`+17/-0`，`p=1.53e-5`，CI `+27.5~+57.5 pp` | 当前 canonical 复现 |
| R0 conditional-B | `3/26 -> 20/26`；SPL `0.0384 -> 0.6229` | geometry 直接修复 Revisit |
| B0 bearing interface | metric `20/26`，fixed 2.5 m `20/26`，`+1/-1, p=1.0` | aggregate 增益不需要把距离暴露给 controller |
| Top-K | K=1/K=8 均 `18/40`，`+1/-1, p=1.0` | 候选宽度不是瓶颈 |
| Learned ranking | Phase-B AUC `0.95~0.96` vs DINO `0.91~0.92` | 候选级特征有信息 |
| Learned decision | top-1 `25/34 < 26/34`；OOF `84.5% < 87.3%`；GLP `70.9% < 87.3%` | 排序未转成更好 activation/闭环 |

R0 的六条 residual 中，4 条 router inactive，只有 2 条 router-active controller failure。
因此只换 controller 的最大净空间约为 2/40，更大杠杆在 activation/direction supply。

旧 8 条 failure 的真共视分解为：目标从未被观测 1、正例在 margin 外 2、正例未进
top-8 为 2、alias 锁存 1、RANSAC 误拒 2。因此不能把所有失败都归给 selector。

### 与 NOVEL bearing 的组合性

最新 5090 四臂 factorial：

| A / B | B native | B geometry |
|---|---:|---:|
| A native（A=30/40） | joint 8/40 | joint 23/40 |
| A oracle-bearing（A=40/40） | joint 13/40 | joint 29/40 |

- native-A 后 memory：`8/40 -> 23/40`，`+15/-0`，`p=6.10e-5`；
- bearing-A 后 memory：`13/40 -> 29/40`，`+16/-0`，`p=3.05e-5`；
- 完整组合 vs all native：`8/40 -> 29/40`，`+22/-1`，`p=5.72e-6`。

这证明 bearing 改写 A 路径和沿途 memory 后，geometry memory 仍然显著有效。
但 bearing 来自 Habitat oracle，所以 `29/40` 是组合机制结果，不是可部署 SR。

### 3-leg

- End-to-end：A `6/10`，B|A `1/6`，C|AB `0/1`，joint `0/10`；
  先被第二个 Novel-B 卡住，不能说 long memory 是 `0/10`。
- Fixed-prefix conditional-C：native `4/10`，direct geometry `8/10`，graph `6/10`；
  direct 相对 native `+4/-0, p=0.125`，只是 N=10 方向性信号。
- Reverse graph 旧 `19/40 -> 25/40` 有 diffusion-noise confound，严格 conditional-C 又低于 direct；
  因此 direct geometry 仍是默认。

## 3. X-NAVDP

**结论：X-NavDP 确实提供了真实的倒车/deep-rear 执行能力，但它不读 ImageGoal
来选全局方向，完整 R2 也没有显著提高 SR。它是可选 recovery primitive，
不是默认 controller，更不是 Novel direction source。**

### 完整归因

| 实验 | 结果 | 结论 |
|---|---|---|
| Checkpoint audit | 共享 1062 tensors exact equal；PointGoal model 1329 tensors missing=0 | post-training 主要是 PointGoal actor/Q/signed control，不是 ImageGoal |
| N=9 direction probe | mixed 8/9，X 7/9，base pure PointGoal 9/9 | X 不是全局更强 actor |
| Rear mode | -180° fidelity：base `0/9 -> 9/9` | X 确实新增后向模态 |
| X cross-request Q | oracle hit 4/9 | Q 不是 ImageGoal 方向源 |
| N=8 short horizon | signed vs forward 8 wins/0 losses | 有 deep-rear 短时 progress 能力 |
| G1b full-B | mixed/X 四臂全为 6/7 | 效率改善，但唯一 failure 的 router 未激活，无 SR 机会 |
| D1 历史 failures | contemporary eligible 0/5 | 旧非确定轨迹不能当当前配对分母 |
| R1 selected residuals | official X rescue 2/2，base rescue 1/2 | 确有 deep-rear opportunity，但是 failure-conditioned |
| E1/E2 official MPC | static 9/9，Habitat smoke 成功 | 官方 signed MPC 移植与安全契约有效 |
| Complete R2 | mixed 20/26，base 20/26，official X 21/26 | X vs mixed `+2/-1, p=1.0`，无显著 SR 优势 |

Official MPC 已真实移植，不再是 pure-pursuit 近似：N=9 rear fidelity `9/9`，mean request
error `1.37°`，solver status 全零，bridge error `<2e-9 m`，E2 的 40/40 controls 全部通过。
因此 R2 没提升不能归因于“没复现官方 executor”。

### Complete R2

| Controller | B given A | vs mixed | Implied joint |
|---|---:|---:|---:|
| Existing mixed ImageGoal+PointGoal | 20/26 | -- | 20/40 |
| Base pure PointGoal | 20/26 | +1/-1 | 20/40 |
| Official X + MPC | 21/26 | +2/-1, `p=1.0` | 21/40 |

- 两个 gains 都是 `|bearing|>=150°` deep-rear；
- 一个新 loss 在 `-115.55°` side-rear，跑满 500 steps，含 483 reverse frames；
- 19 条共同成功上，X 相对 mixed 平均路径 `-1.57 m`，SPL `+0.136`。

独立离线复算进一步显示：17 条 `|bearing|>=135°` 的 descriptive deep-rear 组中
mixed/base/X=`15/15/17`，而 4 条 `60~135°` 组为 `4/4/3`。这解释了 X 能力为何被一个
side-rear 新 loss 抵消；分组来自 consumed R2，只能做机制描述，不能变成部署阈值。

路径/SPL 只是 success-conditioned efficiency，不能换成 SR claim。

X-NavDP README 的 `61.20% -> 84.28%` 属于 Isaac-Lab PointGoal/multi-embodiment benchmark；
我们测的是 MP3D ImageGoal-Revisit 中 memory 给出 PointGoal 后的局部执行，两者不能直接对等。

### 下一步

1. 不把 X 全局替换 mixed NavDP；
2. 不在 consumed pool 上事后部署 `|bearing|>=150°` selector；
3. 只有 fresh protocol 中预注册的 deep-rear recovery gate 通过，才保留 X 作为局部 primitive；
4. 当前不再为 X 投入大规模 HPC；主优先级回到 REVISIT bearing adapter 与 geometry
   evidence recall。
