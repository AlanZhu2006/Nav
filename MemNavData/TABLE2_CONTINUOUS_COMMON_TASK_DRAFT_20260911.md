正式总体未封存、未提交 HPC，未修改任何 controller/证书。

## 1. 已完成与真正剩下的事

本机已跑通 GEM 自己的 `A→B-Revisit→C-Revisit`，没有重放、借用另一臂历史或重置
first40 尺度。前向 Novel-B 也实际执行过，虽导航失败，目标切换和状态延续均通过复查。
接下来不需要再证明循环能执行，而需要确定两个方法接收**同一个后继目标**的方式。

本机已证实：两臂成功到达同一 B 后，即使终点只差 2.16 cm，实际观察历史仍可能不同。
按 native 历史选择的四个 C，在 GEM 历史上全部不满足对应的原构造条件。
在原有限候选池继续测量，仍有 7 个 Novel、56 个 Revisit 候选满足两臂的几何/支持检查。
这是一个已消费案例的供给诊断，且 Revisit 的视图扰动提案来自 native 历史；尚不是正式
对称构造器，更不是这些候选已经导航成功。

## 2. 推荐：连续执行，逐段共同发题

```text
同一 A 目标、同一初态
    Native 执行自己的 A        GEM 执行自己的 A
                ↓ 到达后共同构造同一 B 图
    Native 接着执行自己的 B    GEM 接着执行自己的 B
                ↓ 到达后共同构造同一 C 图
    Native 接着执行自己的 C    GEM 接着执行自己的 C
```

等待另一臂发题期间只暂停仿真时间，不产生机器人动作、重复观测或新 memory 帧。
每臂的物理末态、短期观察、LingBot 状态和历史均原样延续。
同一阶段的目标图一旦发出，不能因导航困难再修改。

起始任务数和 NNN/NNR/NRN/NRR 配比提前固定；后续不补入新的成功来源。
两臂都存活时，同一候选必须分别通过**各自**的原构造要求：

- Novel：从各自实际朝向看均为 ±60° 前向；距离 2–9 m；当前视图和完整历史共视均 <0.10。
- Revisit：沿用 0.55–0.90 支持、可用历史帧和小视角扰动要求；允许后向。
- 相机、目标照片采样、步数预算、mono depth、strict certificate 与 2.5 m residual 不变。
- 候选顺序与选择只使用构造信息，不能读取候选未来的导航结果、critic 或方法预测。

若一臂前段失败，它仍留在起始分母，后续记为未尝试，另一臂可继续自身链。
不会要求双方都成功才保留该 episode，也不会在 C 重新凑成 50/50 的成功样本。

这保留了用户要求的完成阶梯 `N → N_A → N_AB → N_ABC`，同时避免两个存活方法
各自领取不同目标后，误报为同任务配对。

## 3. 必须先明确的实验定义

上述方案是**共同在线发题的连续多目标实验**，不是出发前已固定全部三张目标图的 benchmark。
后继任务会依赖已执行的两份历史，因此也不是独立于被测方法的固定任务分布。
如果论文要坚持“出发前固定完整目标序列”，就不能同时保证它对所有不同实际历史都保持
相同 Novel/Revisit 身份、都保持前向。两者不能靠代码检查自动兼得。

用户已确认这一选择。正文应按上述在线发题定义介绍实验，不能改称预先固定三目标。

## 4. 实现前还要检查什么

1. **对称共同候选。**现有 native 提案诊断只能用于开发。实际共同采样不能固定偏向
   native，Revisit 的近邻视图来源也要在两份历史上分别核对，不能只检查一边的扰动距离。
2. **距离供给。**原案例共同 Novel 为 2–4 m 1 个、4–6 m 6 个；共同 Revisit 为
   2–4 m 45 个、4–6 m 11 个，6–9 m 均没有共同候选。不能把“都有合规目标”当作
   三阶段距离分布已经配平；需在更多已声明来源上检查，不按 SR 挑选。
3. **空供给。**没有共同合规目标是任务构造终止，不是某臂导航失败。不得补换原分母、
   放宽条件或把未发出的 C 填成失败。若正式总体仍有此类未观测项，不能报告为完整的
   已观测三段 SR；需明确构造损耗及其对完成率的上下界影响。
4. **运行状态。**共同发题需要保留两套持续运行的自身状态。现有本机入口每次只运行
   一臂，不能直接套原共享前缀的 sbatch 作为连续比较；也不能用重放代替状态延续。

下一步完成两臂状态保持与对称构造的小测，最后封存
正式任务。没有必要为了赶提交，把已经发现的不同目标/不同历史问题带入大规模结果。
