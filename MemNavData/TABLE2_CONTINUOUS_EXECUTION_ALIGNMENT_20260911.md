## 1. 现有实现实际测什么

`table2_mixed_hpc.py` 的 A 由 native 实际执行；B 在同一 A 历史上分别测试 native/GEM。
但进入 C 时，参考前缀只取成功的 native-B，并恢复其 A+B 物理末态与历史。
GEM-B 的实际行为和成败没有成为 GEM-C 的状态来源。

因此现有汇总器正确地标注为 stage-conditional paired queries，不是 autonomous joint SR。
论文当前 `tables/continual_meeting.tex` 也只报告条件第三目标：Revisit 8/20→17/20，
Novel 4/20→4/20；不能把这两个数字解释成完整 A→B→C 的成功率。

与 Table I 并非完全重复：它使用更长的实际 A+B 经验，能检验中间任务后的记忆效用。
但两者都是“给定历史，比较随后查询”的证据，无法充分回答连续多目标的系统级效果。
这一层适合作为受控分析，不再作为本次主表重跑的最终交付。

会议清单 `paper/会议实验优先级与执行清单_2026-08-27.md` §4 允许受控前缀，
但同时要求逐 leg 完成情况和 joint success。用户本次进一步明确，主结果以实际连续执行为准。

## 2. 新主表的执行要求

```text
Native：实际 A → 自己的实际 B → 自己的实际 C
GEM：   实际 A → 自己的实际 B → 自己的实际 C
```

- 每个方法从同一声明初态开始，但后续必须继承本方法的实际位置、yaw、RGB 历史、
  短期状态及单目几何状态；goal 切换不替换成另一个方法的轨迹。
- 每条链只在 episode 开始重置；不能在 leg 边界传送到参考终点、填入 expert 帧、
  补走失败段或借 native-B 补全 GEM 的经历。
- Novel/Revisit 标签仍仅供构造/分析使用，不用标签强制 GEM 在某一段走 native。
- 不为统一 A/B/C 的 SR 改 checkpoint、相机、深度、证书、2.5 m residual、执行器或预算。
- 继续保留 B、C 双角色的四种计划序列：NNN、NNR、NRN、NRR。
  它们是不同完整 episode 分支，不是在一个 episode 中先跑 B-N 再跑 B-R。
- C 的 B-role 50/50 应落在事先安排的**序列配比**上，不能在看到 native-B 成功后
  筛选等量成功历史，再把该条件总体叫完整多目标主表。

### 用户澄清：Novel 三阶段条件接近，Revisit 沿用同一规则

本表不要求 A/B/C 的实际轨迹、末态、历史长度或 SR 相同；要控制的是可设计的任务难度，
避免第一段容易、后段因另一套构造规则而系统性变难。

- A/B/C-Novel 使用同一前向定义、2–9 m 距离及三个距离档、同一目标照片朝向生成规则、
  同一相机与初始不可见性规则。历史中无支持的定义仍基于各自完整实际经历。
- 不能只核对“三段都在 2–9 m”，还要报告实际距离档与起始角度分布，防止 A 集中短距离、
  B/C 集中远距离。检查结果用于识别构造偏差，不按导航成绩挑选或补换任务。
- 路线绕行程度、目标照片视角及初始可见性继续做原有诊断；不新增路线门限或逐阶段特例。
- B/C-Revisit 沿用相同的原始共视、位姿扰动、距离和有效历史标准，允许回头。
  “相同”按统一构造标准理解，不强制连续两段都以同一个已经到达的点为目标，制造零距离任务。
- 连续执行造成的真实状态与支持变化保留并记录，不通过重放、GT 预转向、改 policy 或深度
  把三段人为做成同一个查询。最终依旧统计两种方法各自的累计完成阶梯。

## 3. 统计口径

用户进一步明确要“阶梯状：一开始很多，三次逐段减少”。对应的是同一起始总体的
任务存活链，而不是每一阶段另找一批查询：

```text
起始 N → A 成功的 N_A → A+B 均成功的 N_AB → A+B+C 均成功的 N_ABC
```

满足 `N_ABC ≤ N_AB ≤ N_A ≤ N`；如果某阶段全成功，允许持平，不人为要求每阶下降。
Native/GEM 分别形成自己的存活链。不能取两臂共同成功子集、不能用 native 的成功
轨迹补另一臂，也不能为了使第三段样本足够而重新补入历史。
B/C 角色序列在起始任务总体中预先登记；若同一起点派生多条完整序列，必须从起始 N
就分别计入，不能到 B/C 时临时扩成更多主表任务。构造损耗另列，不能冒充导航掉队。

对每一种完整任务序列，起始分母 N 在正式测试前确定，保留前段失败。

- 到 A 的累计完成率：A 成功数 / N。
- 到 B 的累计完成率：A、B 均成功数 / N。
- 三段 joint SR：A、B、C 均成功数 / N。
- 另报平均完成目标数及逐 leg SPL；条件 B|A、C|AB 可作诊断，但不是主分母。

本次按上述阶梯语义采用“失败即结束本链”：失败后未尝试段标记 not attempted，
其整链 joint 为失败；不能把未尝试段当成独立执行失败用于条件 SR，也不能从起始 N 中删除。
基础设施故障仍单列，不伪装为导航失败。

阶梯必须单调不增的是累计成功数量/累计完成率，不是每一 leg 的条件成功率。
后者的分母依次为 N、N_A、N_AB，可升可降，不能人为调到相同或单调。

同一目标序列、初态和 seed 才能形成任务级配对。各方法历史不同是完整系统的作用结果，
不再要求 B/C 的起点、图像历史或逐动作轨迹完全相同。
不得把不同条件子集的 A/B/C 成功率相乘来计算 joint。

## 4. 必须先解决的目标构造边界

前向 Novel 要求保留，但不能忽略连续执行与固定目标之间的实际约束：

1. 两个方法到达 B 后的位置、朝向和观察历史可能不同。
2. 同一个固定 C 目标，不自动保证对两边都前向，也不自动保证对两份历史都 Novel/Revisit。
3. 给各方法分别挑更合适的 C，不能再声称是同目标序列的配对比较。
4. 把双方恢复到同一个 native-B 末态虽然能统一条件，却重新退回共享前缀实验。

因此还需要在本机验证共同目标序列如何构造、实际支持/方向如何记录，以及构造供给不足
如何与导航失败分开。不能通过改目标照片 yaw、放宽共视、预转向或事后按 SR 筛选来掩盖。
在这项问题解决前，不把现有 v3 bundle 提交为“完整 multileg Table II”。
