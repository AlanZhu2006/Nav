# Table II v3：向前 Novel，方向不受限的 Revisit

版本：`table2_forward_novel_actual_mono_20260911_v3`。
依据：用户在 2026-09-11 明确要求“主要是 novel 不要回头，revisit 可以回头”。
这是在 v2 的 A 结果已知后作出的任务定义修订，不冒充未见结果的首次预注册或 held-out 确认。
v2 协议、源码封装、144 个 A 结果及已经执行的 B 单独保留，不覆盖、不改标签、不混入 v3。

## 1. 唯一研究设置改动：Novel 初始方向

A、B-Novel、C-Novel 的初始最短可行路线首段，相对机器人**真实初始 yaw**必须在 ±60° 内，
沿用项目既有 `front` 定义。选择前方目标，不按 GT 将机器人预先转向目标。
B/C 必须继承实际前段末态 yaw；运行过程中 NavDP 仍可自由转弯、避障或进行必要探索。
此规则不承诺整条路线绝不转弯，也不保证目标的直线方位始终在前方。

Novel 只在三个距离格 `[2,4) / [4,6) / [6,9]` 中平衡，不再配额采样侧向／后向。
Revisit 保留原来的前／侧／后方向、历史位姿扰动、共视规则及九格供给内匹配；不强迫回访向前。
两种角色因此不是同难度任务。主比较仍是同一查询上的 native/GEM，而不是两种角色原始 SR 相减。

## 2. 保持不变

- 同一容量审计的全部 18 scenes、每场景 8 个声明源，共 144；场景、起点、seed、独立初始 yaw、
  目标照片朝向生成规则和源顺序保持原声明。只改变 Novel 可选的方向格。
- 只复用 PT1/gapfill 资产与初始条件，不将 expert 轨迹或旧在线轨迹作为新 A 的 memory。
- A 重新执行 frozen mono NavDP，实际 RGB/几何构成 H_A；不只挑 v2 中成功或前向成功的 A。
- A/B/C 同层、初始测地距离 2–9 m，当前起始视图共视 <0.10。
- Novel 对完整实际历史 max-covis <0.10，目标照片独立八档世界朝向，拒绝空白无效视图。
- Revisit 在实际历史位置附近平移 0.20–0.80 m、偏转 12–45°，RGB MAE ≥5，
  全历史 max-covis [0.55,0.90]，runtime-eligible 历史支持 ≥0.55；不复制历史 JPEG。
- 480×270、相机安装高度 0.5 m；单目 LingBot 几何＋高度先验，无传感器／simulator metric depth 输入。
- frozen native/GEM、2.5 m bearing residual、原授权参数、`bounded_standard/rgb_v1/source_rgb/heading_on`、
  horizon=8、600 ticks、原 stuck 规则与距离 <1 m 到达测量均不变。不重新引入 GT 落点投影。

## 3. 全量构造与阶段流程

Novel 保持 10,000 次空间提案预算和每格最多 12 个视觉候选，先筛方向，再检查完整历史支持。
不通过增大重试次数、把机器人转正或重新选取成功轨迹来补缺少的前方 Novel。
候选菜单形成后才做总体匹配：Novel 的三个前向距离格、Revisit 的原九格分别最小化计数平方和。
若真实末态前方没有满足不可见／距离条件的 Novel，记录构造失败，不能用后向目标顶替。

所有 A 菜单及选择必须先于任一 v3 导航封存。全部 144 个源保留；无前向目标的源单列构造损耗。
源 identity / yaw / seed 复用不等于结果复用，v3 中的 actual A 仍从空历史重新运行。

```text
actual mono A（前向 Novel）→ H_A
  ├─ B-Novel（前向）→ native/GEM 配对
  └─ B-Revisit（任意方向）→ native/GEM 配对
成功 native-B 的实际 A+B 历史，按 B 角色 50/50
  ├─ C-Novel（前向）→ native/GEM 配对
  └─ C-Revisit（任意方向）→ native/GEM 配对
```

B 只使用 A 成功且两种 B 可构造的前缀。C 只使用 native-B 成功且两种 C 可构造的前缀；
按预定 source 顺序取两类供给的较小数量，不要求同一个 A 的两种 B 都成功，不使用 GEM-B 替代。
所有失败、缺目标、未纳入来源保留。C 不保证达到指定 N；不通过增加场景或成功率筛选补齐。
本表是逐阶段共享前缀实验，不是自主三段 joint SR；不能保证 A/B/C 的 SR 相等。

先做本机单元测试及真实场景构造检查，特别核查：
Novel 数值角度 ≤60°、无前向目标时留空、Revisit 允许后向、B/C 不改真实末态 yaw、
完整历史支持约束与 C 50/50 保持、runtime 请求不包含 role 或 GT 方向提示。
新的协议、source declaration、payload 和 bundle 单独封存；不得原地修改 v2 已提交任务的参数。
HPC 按共享 SSH 手册，用既有容器与依赖，先通过 imports/CLI/资产预检，再提交阶段首项。
每查询 native/GEM 同一任务、同机同宿主服务配对，逐角色平衡 arm 顺序；任务 1 GPU / 1 小时。
资源设置继承 v2 已记录的调度补充：A 并发上限 4，B/C 仍为 2，实际按 QOS 调度；
技术验收只检查执行与归档，不要求导航成功。
