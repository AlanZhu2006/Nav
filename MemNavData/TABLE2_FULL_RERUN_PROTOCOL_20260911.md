# Table II 完整重跑：实际单目历史上的逐阶段 Novel / Revisit

冻结版本：`table2_balanced_actual_mono_20260911_v2`。
本协议先于新导航结果制定；不覆盖旧 Table II 或正在运行的 8-source pilot。

## 1. 科学问题与表格

A 用 frozen mono NavDP 实际采集经验。B 从同一 A 末态产生独立 Novel / Revisit 查询。
成功的 **native-B** 分支形成实际 A+B 前缀；C 再分别查询 Novel / Revisit。
两条 B 分支不互读历史；GEM-B 不能代替失败的 native-B 给 C 提供记忆。

主表五行：A-Novel、B-Novel、B-Revisit、C-Novel、C-Revisit。
A 报告共享采集 SR/SPL；B/C 分别报告 native/GEM 的 SR、实际位移 SPL 与配对增损。
所有条件分母和构造损耗保留。该表是**阶段条件、共享前缀的记忆效用比较**，不是自主 A→B→C joint SR。
C 的附表展开前序 B 角色，另记录 A-only、B-only、both、intermediate 支持来源。

## 2. 固定源总体

从本地 40-scene PT1 / gapfill inventory 的已完成离线全量容量审计中，采用全部 **18 个合规 MP3D scenes**。
合规指至少有一条诊断 carrier 在旧 expert A/AB 前缀下找到 B/C 未见视图，且旧 A/B 末态间距离在 2–9 m；
该筛选从未读取新旧 native/GEM 的 query SR，也不声称能保证新 actual-online 前缀的构造成功。
每场景声明 **8 个新 A 查询，共 144 个源**，到此为止，不按看到的成绩追加来源。
每个场景按旧 carrier 的字典序轮转复用物理起点和相机内参；每个新查询拥有独立初始 yaw、goal proposal、policy seed。
同一起点的重复使用明确保存 `carrier_source_id / reuse_index`，不是额外独立场景；统计按 scene 聚类。

不复用旧目标图、expert 路线或 expert 末态作为运行时历史；不把本轮称为新 held-out confirmation。
PT1 只供给场景资产和初始条件。所有 A、native-B 的 RGB 历史均须重新实际执行获得。
前期 expert 前缀容量审计只是构造诊断，不计入本轮导航结果。

## 3. 共同目标构造

- 全部阶段使用同一 480×270 相机和来源内参，固定安装高度 0.5 m。
- 目标初始测地距离 2–9 m；距离格 `[2,4) / [4,6) / [6,9]`。
- 前/侧/后按最短路线首个非平凡方向与**实际初始 yaw**之差，绝对角度 `≤60 / (60,120] / (120,180]` 度划分。
- 整条构造最短路线相对起点楼层高度偏差不超过 0.20 m；不引入跨楼层任务。
- 初始 A yaw 独立于目标和最短路；B/C 继承真实前段末态 yaw，不预先替机器人朝向目标。
- **所有查询的目标与当前初始图共视 <0.10**，避免 A 目标初始可见、B/C 不可见的旧不对称。
- 不要求同一前缀的 N/R 指向相同方向。运行时不给策略任何角色标签或构造共视数值。

Novel 在每阶段都用同一几何提案、独立八档世界朝向的目标照片规则：
非空有效深度表面，且相对完整因果前缀所有帧的 max-covis <0.10。A 的空历史不豁免当前视图检查。
GT 深度、位姿、NavMesh 只用于离线构造与测量，不能作为 controller 的输入或落点修正。

Revisit 从实际完整前缀每 8 帧的历史地址（从 frame 39 至末尾前 16 帧）产生平移/转向扰动：
平移 0.20–0.80 m、朝向变化 12–45°、RGB MAE ≥5；不是历史 JPEG 的复制。
完整历史 max-covis 在 [0.55,0.90]，frame≥8 的 runtime-eligible 历史至少有 0.55 支持。
目标最终位姿也满足上面的 2–9 m / 同层 / 初始不可见条件。
不同共视难度由独立的 covisibility ablation 回答，本轮不改在线 certificate 阈值。

## 4. 菜单、总体配额与条件分母

每个状态固定最多 10,000 个空间提案，每个距离×方向格最多保留 12 个 Novel 照片候选；
按事先固定的顺序取每格首个合规目标。Revisit 扰动交错覆盖整段历史，最多 384 次完整视觉检查。
取满菜单或预算耗尽就停止，不因导航结果重采样。

目标不是“每个历史第一个碰到什么就用什么”。每阶段先汇总菜单，再作全局单位容量最小费用匹配：
每个可构造来源选一个目标，最小化九格计数的平方和。只有候选地址与构造属性进入选择器，无模型分数或 query SR。
此操作让**现有供给下的分布尽可能平衡**，不声称在缺少候选时也能强制九格等量。
必须报告实际九格计数、距离分布、当前可见性和空菜单，不把缺格换成其他标签。

- A 的全部 144 个候选菜单与选择先于任一新 A rollout 封存；无合规目标的源单列构造失败。
- B 只从成功 A、且 N/R 均可构造的共享前缀选取，两种角色分别全局匹配；B 分母不因 B 成败改变。
- C 的参考前缀只来自成功 native-B 且 C-N/R 均可构造的分支。
- C 前缀来源按声明 source 顺序，全局取两类 B 来源较小供给量，N-B / R-B **严格 50/50**。
  不要求同一个 A 的两种 native-B 都成功；不以 GEM 成败或 C 成败筛选。
- 固定 C 来源后再匹配两种 C 查询。未选、失败、不可构造来源全部留在 flow ledger 中。

预计最多 A 144 rollouts、B 576 rollouts，C 数量由上述冻结构造及成功前缀决定，最多 1,152 rollouts。
这是有限总体任务，不保证一个晚上完成，也不保证 C 达到旧表的 20 条有效前缀。
若供给不足，报告真实分母与统计能力，不临时改变构造或不断追加来源。

## 5. 冻结运行时与控制变量

沿用最新已经修复并验证的 `bounded_standard / rgb_v1 / source_rgb / heading_on`。
不新增 GT 落点投影；不偷换为另一个 MPC，也不修改 NavDP 或 GEM checkpoint、检索和授权参数。
只有单目 LingBot 几何与一次相机高度先验；无传感器或 simulator metric depth 输入。
单次 query 最多 600 ticks，execution horizon=8，success_dist=1 m；保存最后动作后的真实落点。
短程零深度起步等既有行为保持原契约，不能在看到结果后单独给某个方法换深度条件。

每条 query 的 native/GEM 在同一个 Slurm array element、同一进程宿主和 GPU 上配对；
共享 Goal RGB、seed、物理起点、朝向、实际 prefix 和 replay 收据。每种角色内部平衡 arm 顺序。
GEM 未接管时验证动作、采样轨迹、深度事务与 native 完全一致。
训练/权重不变并不豁免构造偏差；不承诺 A/B/C 的原始 SR 必须相等。

## 6. 执行与验收

先完成本机的单元检查、真实渲染和构造供应；本机已有服务不关闭、不重置。
HPC 按共享 SSH 手册使用 yz11502 的 alantorch master。
封存单独 source bundle 与 payload；复用已成功的容器/依赖路径，含 multipart CRLF 修复。
先检查模型 import、CLI、资产与运行参数；A/B/C 每阶段先以首个有查询的任务作技术验收，
该阶段其余任务依赖它成功归档，再继续扩展。不能用导航 SR 高低作为技术通过条件。
正式任务复用该运行时、每个 array element 1 GPU / 1 h，并发上限 2，实际资源服从 QOS。
阶段顺序：A → 汇总并选择 B → B → 全局选择 C → C → 汇总/独立复算。
技术失败保留原日志后精确重试原 query；不得把超时当导航失败，也不重采样容易目标。

统计：逐场景聚类 bootstrap、配对增损和 exact McNemar；共享来源不是独立场景。
实际位移 SPL 从逐动作位置加末动作终点积分；不得恢复帧数×名义步长的旧估算。
主效应是各阶段各角色同 query 的 native/GEM 差异。
A/B/C 原始 SR 的横向比较同时展示构造分布；若分布仍不同，不归因为记忆或阶段本身。

完成标准：所有预定源有成功或明确构造/技术状态；所有纳入查询双臂齐全；SR/SPL可独立复算；
C 50/50、prefix 隔离、终点保存、无接管精确一致通过；输出新结果总账，不覆盖旧论文数据。
