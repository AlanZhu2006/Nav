## 构造与执行顺序

1. 两个 A 的新目标都在启动导航前选定，再从空历史实际执行 A。
2. 成功 A 的真实观测重渲染并核对每帧 JPEG，形成共同 A 前缀。
3. 从 A 的实际末态构造 B-Novel / B-Revisit，两个目标均在任何 B 臂运行前固定。
4. 每种 B 独立重置、重放同一 A 的实际 RGB 和 NavDP 决策帧，再运行 native/GEM。
5. 对各自成功的 native-B，将 A 与该 B 的实际观测拼接；先核对 B 首态恰为 A 真实末态。
6. 各分支独立构造 C-Novel / C-Revisit；不使用 GEM-B 或其他 B 分支的帧替代。
7. 在任何 C 导航前，按预定来源顺序等额选取两种 B 来源；供给不够则明确缺额，
   不为了跑通而改为不平衡的正式 C 结果。所有 B 结果及未入选前缀仍保留。

A 失败则无后续合法前缀；B 失败仍计入 B 结果，但不传送到目标构造 C。
本机验收以接口和历史正确性为准，不以高 SR 为门槛。

## 目标供给预检，与正式配额的区别

- Novel：同层、2–9 m、0.30 m clearance；目标照片按共同八档独立世界 yaw 规则渲染。
- 候选使用既有最多 5000 次空间提议、各方向最多 16 个的池。
- 本机仅检查供给，按 proposal index 选择首个视觉条件合规目标，**不声称方向或距离已经匹配**。
  正式总体的共同距离、方向配额仍须根据供给审计在运行正式查询前冻结。
- B/C Novel 检查全部实际前缀，最大共视严格 `<0.10`，包括早期不可检索帧。
- Revisit 在真实历史位置附近重渲染，位移 0.20–0.80 m、yaw 差 12–45°、像素 MAE ≥5；
  不复制历史 JPEG。按实际 runtime 合法地址 `frame >=8` 检查最大共视 `[0.55,0.90]`。
- Revisit 扰动源仍从 `frame >=39`、距尾部至少 16 帧的历史每隔 8 帧选取，
  按时间顺序取首个合规目标；不沿用旧构造器的“最靠近 3 m”排序。
  首轮小测只取最早 6 帧；B 配对完成后的 C 构造检查发现此限制遗漏了整段 B，
  已在新 C 查询运行前移除。正式候选池不继承这个局部加速限制。
  **2–9 m 只检查最终扰动目标，不预先限制历史源帧距离。**离线已找到源帧
  1.866 m、最终目标 2.086 m、合法历史共视 0.707 的反例；提前限制源帧会误删合规目标。
- 共视统一使用原实现和 `DEPTH_TOLERANCE_M=0.30 m`。
  分别记录完整历史最大共视、合法地址最大共视和查询首视图支持，不混用分母。
- C 分别计算完整 A、B 的支持：A-only / B-only / both / intermediate。
  来源帧属于 A 不代表 B 没见过该目标。前序 B 的 50/50 不等于支持帧必须各占一半。

这些是离线构造条件，不改变 GEM 在线证书。GT 深度/位置用于构造和评分，
策略端仍只接收 RGB、共同单目深度及经过证书的方向。

## 运行与验收

- 两臂同机、同服务进程、同目标/前缀/seed，顺序交替；600 ticks、horizon 8、1 m 位置评分。
- `bounded_standard / rgb_v1 / source_rgb / heading_on`、canonical GEM 保持与修复版相同。
  此处是标准 Habitat 碰撞约束的运动仿真，不声称刚体动力学或自主 STOP。
- 新目标重建查询状态；各次查询的 LingBot 流和 first-40 收据由同一实际前缀恢复。
  NavDP 只重放原决策帧，重放不采样 diffusion；不把 expert 控制结果灌入短期队列。
- 显式记录每个动作前/后的状态及终点，独立积分实际路径并复算 SPL。
- GEM 全程未接管时，比较逐次候选、轨迹、动作、图像与深度摘要是否与 native 完全一致。
- C 仅报告条件于成功 native A/B 的共享前缀结果，不能乘出 GEM 自主三段 joint SR。

本机模块测试不代表 CUDA 网络验证通过。Table I 的两项回执异常另行补跑中，
本轮不删除对应检查；若本机出现同类异常，保留原始失败，不统计为已通过。
