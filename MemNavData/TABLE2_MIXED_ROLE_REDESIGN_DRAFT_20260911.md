# Table II 重设计：B/C 双角色、真实共享前缀与可解释的逐段比较

日期：2026-09-11。状态：本机实际分支预检完成；正式总体未冻结、未提交 HPC，未修改论文或导航方法。

## 1. 推荐结论

保留 Table II「历史逐步积累时，记忆何时产生收益」的目的，扩展为：

| A | B | C | 主要问题 |
|---|---|---|---|
| 初始 Novel | Novel | Novel | 连续遇到无历史支持目标时是否发生误干预？ |
| 初始 Novel | Novel | Revisit | 探索新区域之后能否使用已经积累的历史？ |
| 初始 Novel | Revisit | Novel | 完成一次有历史支持的任务后，能否切换到无支持目标？ |
| 初始 Novel | Revisit | Revisit | 相邻两次有历史支持的查询能否分别完成？ |

B 的角色相对于实际 A 历史定义；C 的角色相对于它所在分支的实际 A+B 历史定义。
角色仅供构造和评分，运行时始终只接收目标图及合法的因果观测。

目标不是让三个阶段 SR 接近，更不是让 SR 随阶段上升；目标是消除隐藏的构造不对称，
让每项方法比较都具有明确的任务、历史和分母。

## 2. 为什么不能直接把旧表补成四列

已核验的旧 Table II 并非同难度逐段重复：

- A 有 187/196 条前向起步，B 有 108/183 条后向起步；A 使用两段式载体的
  `path_aligned` 初始化，之前三段式生成器的修复没有应用到这批源任务。
- A 目标图沿专家接近路线向前拍摄，B 目标图使用独立世界朝向；专家照片不等于专家历史泄漏，
  但两者的视图分布确实不同。
- A/B 平均最短路为 5.394/5.487 m，不能简单归因于 B 更远。
- A 的 196 个任务与 B 的 183 个候选不是一一对应，B 来自 67 条 A 历史。
- 修复版新 A 的 45 条合法历史也不能直接当作难度匹配总体：Revisit 距离约 2.01–3.87 m，
  Novel 约 2.05–8.99 m。该批 A 又保留了原始起点和目标图。

这些结果保留为旧协议证据；新的设计版本不能把旧数字拼接成一条新的连续序列。

## 3. 主实验选择：controlled/shared-prefix，而非伪造完整联合成功率

本草案优先延续会议清单允许的共享前缀设计。主比较只用 native 与 GEM；
raw 和定位模块消融由其他表承担，不在这里展开所有模型组合。

### 3.1 A 与 B

1. 用修复版 frozen mono NavDP 实际执行 A，记录完整实际 RGB、末态及因果状态。
2. 从每条合规 A 的同一末态，构造一个 B-Novel 和一个 B-Revisit。
3. 每个 B 目标分别运行 native/GEM，恢复同一 A 前缀、物理起点和目标。
4. 两种 B 是独立分支；B-Novel 的经历不能流入 B-Revisit，反之亦然。
5. 每条 A 每种 B 只保留一个预先选定目标，不因 B 导航失败再换目标补成功。

A 是共享采集结果；B 则是两个有明确分母的方法配对行。

### 3.2 C 接在哪条实际 B 之后

主表预先指定 **native-B 为参考前缀采集器**，在两种 B 角色中分别执行以下步骤：

1. 保留实际完成 B 且能够构造 C 查询的参考前缀；B 失败和构造失败都记录在损耗账中。
2. 在这个实际 B 末态及 A+B 历史上，独立构造 C-Novel / C-Revisit。
3. 每个 C 目标分别运行 native-C / GEM-C；它们重放完全相同的真实 A+B 观测。
4. 不使用专家接续、失败后传送到 B 目标、其他分支的历史，也不将超时记成 B 完成。

选择 native 作为固定采集器不是在宣称它代表所有部署历史，而是隔离 C 阶段的记忆收益，
并延续原 Table II 的前缀来源。C 结果明确条件于 native A/B 成功及可构造性。

**这不等价于「GEM 自己接管 B 后，再连续执行 C」的端到端结果。**
如果要作后一项主张，应另行从 GEM-B 的实际末态和历史继续 C，并单独报告。
不同方法 B 后的状态不同，可以比较完整系统的整体任务表现，但不能把这样的 C 当成同起点配对。
这一额外连续执行实验不在本草案中自动提交，也不拿它替换共享前缀主比较。

不要求同一 A 的两种 native-B 必须都成功才纳入 C；否则会额外筛成「两条分支都容易」的子集。
两条 B 分支各自报告 C 分母。相同 A 派生的多个分支在统计上仍属于同一父历史。

### 3.3 已确认的 C 来源比例：两种 B 各占一半

C 主比较采用相同数量的两类实际参考前缀：50% 来自成功的 native Novel-B，
50% 来自成功的 native Revisit-B。每条前缀同时构造独立的 C-Novel 和 C-Revisit，
因此 **C-Novel 和 C-Revisit 各自的前缀来源都是 50/50**，不是只保证混合总数平衡。

例如两类各 10 条合规前缀，会产生 20 个 C-Novel 和 20 个 C-Revisit；
这只是计数示例，不是已确定样本规模。

先固定源任务池与采样顺序，再按 A/B 实际完成及 C 几何可构造性确定等额前缀，
在任何 C 导航结果产生前封存。供给不等时不能按 C 成绩补齐或择优；
未入主比较的合规前缀仍保留在供给账中。最终数量和缺额由构造审计报告。
主表合并 C 来源，附录保留前序 B 类型的分层；不能隐藏其中一类的损失。

## 4. C-Revisit 返回的是哪里

C-Revisit 不限定为再次返回 Goal-B，更不只按「目标图来自哪一段」归类。
对每个目标分别计算它在实际 A、实际 B 上的历史视觉支持，区分：

- **A 支持、B 不支持**：测试旧记忆经过中间一段后是否仍可使用。
- **B 支持、A 不支持**：测试新增经历是否形成可用的记忆。
- **A/B 均支持**：测试重复使用；不能单独归因于保留 A 或新增 B。
- 支持处于中间区间：保留主查询身份，但不硬归入「仅 A」或「仅 B」的严格归因组。

第一类是最直接的长期保留测试。第二类通常更容易在 Novel-B 后构造；
Revisit-B 可能重走 A，因此不强求它一定产生足够的 B-only 目标。
目标图的来源段、实际支持段、历史年龄与当前导航距离分别保存，不互相代替。

若需要一个最小额外消融，只在严格 A-only 的 C-Revisit 上比较：
GEM 可检索 A+B，或只能检索最近 B。短期几何状态、单目深度、尺度收据及 NavDP FIFO 不变，
只改变可检索的显式历史地址；不把它称为抹除了系统的一切旧信息。

这与之前 `initial_leg_only` 不同：旧实验保留 A、排除 B，测试新增 B 的价值；
这里保留 B、排除 A，测试保留较早 A 的价值。只有新总体中具有严格对应支持时才运行。

## 5. 控制变量：控制任务分布，而不是事后控制 SR

### 5.1 起步与目标视角

- 新采集 A 显式设置非路线对齐的初始 yaw，不再依赖 `auto` 与 `n_legs` 的默认联动。
- A/B/C 都记录前/侧/后初始路线角，使用共同的方向分层设计，禁止 A 几乎全前向而后续阶段集中后向。
- B/C 起点和朝向保留参考轨迹的真实末态；通过离线目标采样平衡方向，
  不在目标发出前用 GT 替机器人转到目标方向。
- 所有目标采用同一相机参数；统一目标照片朝向的采样原则，并检查它相对于接近方向的分布。
  不能 A 默认为接近路线正视图，B/C 却默认为世界坐标随机朝向。
- Novel A/B/C 的推荐共同照片规则为：同高度、同内参、水平相机，目标 yaw 由固定种子独立采样，
  不依赖专家最后一段的朝向；可复用现有八个世界 yaw 档的实现。
  这需要重新构造 A 目标照片，不能把旧 A 的专家末帧直接称为符合新规则。
- Revisit 的真实共视限制仍保留；不能为填满朝向格子而丢弃共视要求，也不能把全部任务改成前向。
- 阶段间仍有真实差异：A 从空历史启动、后续目标受未见支持条件限制、后续深度已有尺度收据。
  因此即使观测到相同方向和距离，A/B 的 SR 差也不是「阶段序号」的纯因果效应。
- 还需检查目标在查询起始画面中的可见支持：A 没有前序任务历史，不意味着首帧一定看不到目标；
  B/C 的历史排除则可能同时排除当前附近可见目标。新总体须记录这一量，
  在构造冻结前明确是否采用共同的起始可见性条件，不能事后按 SR 加条件。

### 5.2 距离和路线

- 使用共同可构造的初始测地距离范围；先审计原 2–9 m 范围的分层供给，再冻结共同区间和配额。
- 同时记录直线距离、测地线/直线比和历史轨迹长度，不能把导航距离与记忆跨度混用。
- 不再允许 Revisit 全集中 2–4 m，而 Novel 保留到 9 m，却据此比较两种角色哪个更容易。
- 构造可行性不足时报告缺格；不根据导航成绩删困难样本或扩大容易区间。

### 5.3 避免重犯「匹配过头」的问题

**不把同一历史的 Novel 目标强制放到 Revisit anchor 的相同方向。**
旧 support-controlled 构造已经显示：这样会让错误的历史方向偶然指向正确 Novel，
放大 raw memory 的 Novel SR。

建议在总体层面平衡距离/方向等可观察分布，目标候选选择不参考 DINO anchor 的方向或运行结果。
相同目标上的 native/GEM 才是严格配对；两个角色目标之间不是只改变支持度的随机因果实验。
小总体若无法同时平衡全部维度，保留分层描述和明确的不平衡，不伪称完全匹配。

### 5.4 历史范围与角色定义

- 同时保存完整实际观测历史和运行时合法的候选历史范围，不能再用 frame≥39 分档、
  却让模型检索 frame≥8 而不披露。
- Novel 在当前分支的完整已观察历史上无足够支持；「见过但暂不允许检索」不能自动叫 Novel。
- Revisit 还必须在运行时确实可读的历史中有支持，而不只是 expert 或不可访问帧中存在。
- 支持查询沿用既有高支持主协议，低共视仍由专门消融承担。具体共视实现、方向与分母在构造前绑定。
- C 的 A-only/B-only 判定检查整段实际 A/B，而不是 DINO top-8、选中 anchor 或单一来源帧。
- 角色与查询候选历史在目标发出时定义；后续观测按冻结运行时处理，不追溯改变原角色。
  当前候选生命周期为 `frozen_at_first_goal_query`，新目标须建立自己的查询状态，不能继承上一目标的缓存结论。

### 5.5 执行与评分

- 使用同一修复版 mono 运行栈、GEM 参数、权重、相机高度尺度规则、RGB/深度配准及执行器。
- 保持统一 600-step、horizon 8、1 m 成功半径，若正式冻结版已有变更则以完整同版配置为准。
- 比较臂共享前缀、目标、seed 和初态；同一运行栈配对、arm 顺序平衡。
- 不混入低共视探索版、额外转向/末端策略；尺度收据不因切 leg 重新估计。
- 仿真状态仅供构造、模拟物理与评分，不能作为策略方向或落点修正；保留已修复的标准碰撞执行。
- 保存最后动作后的末态、完整实际路径和服务收据，直接重算 SPL；不再只保留动作前位置。
- 1 m 位置评分与自主视觉 STOP 是不同问题，本表不因补做 mixed role 而顺便改变到达定义。

### 5.6 Novel 定义与 frozen NavDP 的执行边界

| Novel 查询 | 发出目标时的实际历史 | 构造含义 |
|---|---|---|
| A | 没有前序任务的 episodic history | 正常初始 ImageGoal 导航；不提供历史目标方向 |
| B-Novel | 当前分支的实际 A | 目标图对完整 A 的最大共视 `<0.10` |
| C-Novel，接 Novel-B | 对应分支的实际 A+B-Novel | 对完整 A+B 的最大共视 `<0.10` |
| C-Novel，接 Revisit-B | 对应分支的实际 A+B-Revisit | 对完整 A+B 的最大共视 `<0.10` |

这里的 Novel 是目标发出时缺乏既往视觉支持，不是新场景、全局未知地图、
或永远不能在随后运动中看到目标。共视标签只在构造/分析端计算；
`<0.10` 不是 GEM 的在线判别阈值，也不送给 NavDP。

运行规则保持最小：

1. **同一冻结控制器。** A/B/C 使用相同 NavDP checkpoint、ImageGoal 编码、diffusion/critic、
   重规划和修复执行配置；不增加 Novel token、frontier ranker、oracle bearing 或专用转向。
   本表的 native 是 mono NavDP：深度由共同 LingBot 单目链提供，不冒充原版 sensor-RGB-D baseline。
2. **角色不决定开关。** native 臂始终不让记忆影响控制；GEM 臂对 B/C 的所有目标执行同一规则。
   认证接受才附加 PointGoal，拒绝则保留原始目标图，不附加记忆方向或额外物理朝向动作。
   不能写 `if role == novel: force_native` 来制造零干扰。
3. **拒绝必须保持请求等价。** 两臂共享前缀及同一时刻的 RGB、单目深度、NavDP FIFO 和采样种子。
   几何查询不能额外推进 NavDP 的 FIFO 或随机状态。全过程未接管时检查完整输入、轨迹和动作一致；
   一旦发生接管，后续不同物理观测不能再要求与原始 native 轨迹逐动作相同。
4. **切换目标不清空经历。** 只重建当前目标的 embedding/检索/认证状态，保留真实 RGB 历史、
   LingBot 因果状态及已经建立的高度尺度收据；NavDP 短期上下文按同一原生切换/重放规则处理。
   不把上一 Revisit 的 anchor 或 PointGoal 带进下一 Novel，也不在每段重复 first-40 标定。
5. **没有 SR 保证。** frozen 保证的是模型与执行规则不因角色变化，不保证 A/B/C 成功率相等。
   GEM 若在 Novel 接受，则报告接管与增/损，不能用 GT 标签阻止、删除或改记该样本。

除共同距离/方向/照片规则外，不按 DINO 分数、证书是否拒绝或 native 是否能成功来挑选 Novel。
C 的 50/50 是前序任务配比，不是按 C 难度或 C 成绩配比。后续 Novel 的历史排除条件、
A 的初始尺度建立和 C 的前缀成功条件仍不同，应记录这些差异而不承诺 SR 单调或相等。

## 6. 主表与统计

按已确认的简化版，主表保留五行；SR 写为成功数/查询数，因此不再重复设 `N` 列：

| 阶段 | 当前目标 | Native SR / SPL | GEM SR / SPL | 配对增/损 |
|---|---|---|---|---|
| A | Novel | 待测，共享采集 | 同一 A 采集结果 | — |
| B | Novel | 待测 | 待测 | 待测 |
| B | Revisit | 待测 | 待测 | 待测 |
| C | Novel | 待测 | 待测 | 待测 |
| C | Revisit | 待测 | 待测 | 待测 |

A 的 SR 分母为全部预定 A 源任务，不只统计最终可构造 B/C 的成功 A。
C 两行各自包含 50% Novel-B、50% Revisit-B 的实际参考前缀；表注交代其条件分母。
Novel 行用于检查在新增历史后的干扰，不将其包装为修改了 NavDP 的 Novel 探索能力。

读表的主轴是每行相同查询上的 GEM 相对 native，而不是跨行寻找单调增长。
正文报告 A→B→C 的构造损耗；不能用不同候选总体的 SR 相乘构造 joint。
附录按前序 B 类型展开 C，并报告 C-Revisit 的支持来源；主表合并不意味着省略分层审计。

报告 scene 数、父 A 数、查询数、配对增损、SR/SPL 和 scene-cluster CI。
同一 scene/A 的分支不是独立重复；McNemar 可以作为 episode 配对统计，但不能替代聚类不确定性。
正式检验族、角色加权和样本规模在读新 query 结果前确定，不要求每一个小格都显著。

还没有扣除 C 不可构造、朝向/距离配额和归档完整性条件，不能预报新的 C 样本量。
也不能直接说它们满足本草案的新 A 视角与初始方向设计。

下一步顺序：

1. 本机做不启动策略的供给审计：列出每条已有真实 B 后可构造的 C-N/C-R 及 A/B 支持来源，
   同时检查完整档案、距离和方向分布；不读取 C 导航结果筛选。
2. 选择少量场景验证新的 A/B/C 生成原则及分支恢复。接口验收不以 SR 高低为通过门。
   先核对 Novel 拒绝时的原生请求等价，以及 Revisit→Novel 不残留上一目标的 PointGoal。
   最新 Table I 已发现两项输入/消费回执异常（见状态审计），尚不能称新整条流水线已全部验收；
   若本设计复用该执行入口，需要先查明并关闭对应问题，而不是取消一致性检查。
3. 基于供给与最小有意义效应，冻结源任务数、共同范围、分层配额和统计计划。
   若需改变 A 初始化，先明确新采集成本，不宣称可以零成本套用旧 A。
4. 再准备一次完整的修复版 controlled Table II；不在构造规则尚未确定时直接提交大数组。

工作量按实际供给估算：N 条合规 A 的 B 比较为 4N 次；若两种参考 B 分支分别有
M_N/M_R 条合规 C 前缀，则 C 比较为 4(M_N+M_R) 次。另计 A 采集与可选旧记忆消融。
这不是已确定的任务规模或时间承诺。
